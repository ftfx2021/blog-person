# 人生系统 UX 原型设计（低保真 v0.1）

> 阶段：结构评审稿。本文确认信息架构、页面骨架、主流程和交互规则；高保真视觉稿在风格方向确认后制作。
>
> 设计原则：克制、本地、诚实。系统帮助用户看清事实与下一步，不将完成数量、使用时长或情绪趋势包装成压力指标。

---

## 1. 设计基线

### 1.1 设计目标

1. 首屏先回答“今天做什么”，而非展示大量统计。
2. 规划、执行、记录、回看各自独立；需要关联时由用户主动建立。
3. 所有录入先给最小表单，再按需展开附加信息。
4. 所有异步数据都有加载、空、失败和完成反馈；后台任务可离开页面继续执行。
5. AI 只给基于证据的回答或建议，不替用户写入、更改或诊断。

### 1.2 布局参考与适配原则

本轮采用用户提供参考图的**空间布局**，不复制其品牌、插画角色、功能命名或游戏化表达。

| 保留的布局语言 | 在人生系统中的适配 |
|---|---|
| 左侧常驻日常信息栏 | 日期、今日行动摘要、待办预览、站内提醒、数据安全状态；作为上下文，不作为第二套主导航。 |
| 顶部横向主导航 | Dashboard 与四大模块的一级入口；当前模块以底边线和文字强调。 |
| 顶部宽幅“当前焦点”区 | Dashboard 的“今日行动”主区，承载当日一个最需要面对的行动，而非 AI 指派任务或励志口号。 |
| 中央两列信息面板 | 主列放执行与最近记录，次列放目标、提醒与知识沉淀摘要；面板用于摘要和跳转，不替代详情页。 |
| 全局搜索、提醒、账户入口 | 保留在右上角；搜索默认不检索情绪记录，提醒以抽屉聚合。 |

明确不继承：虚构 AI 助手、卡通角色与装饰插画、待办优先级分级、资源/资产数量竞赛、生活领域量化排名、强激励文案与“提交成果”式操作。

### 1.3 桌面画板与布局

| 项目 | 规格 |

### 1.5 左侧日常脉络栏

左栏为固定信息密度，不能成为第二个 Dashboard：

| 区块 | 内容与规则 |
|---|---|
| 日期与当天摘要 | 日期、星期、待完成待办数、待打卡习惯数。使用中性描述，不显示“效率分”“连续深度使用天数”。 |
| 今日概览 | 待办、习惯、目标提醒的简短计数，点击进入对应页面的已筛选视图。 |
| 待办预览 | 最多 4 条未完成待办，按截止时间；点击打开待办详情，不在此处提供优先级或状态分层。 |
| 提醒 | 最多 3 条未处理站内提醒，点击打开提醒抽屉。超过时显示“查看全部”。 |
| 数据状态 | 仅显示“本地数据正常 / 需要处理”；点击到设置-数据安全。连接异常不使用红色全栏警告，保留错误图标和简短说明。 |

### 1.6 全局状态与反馈

| 情况 | 设计规则 |
|---|---|
| 站内提醒 | 顶栏铃铛显示未读数；点击右侧抽屉，按“今天 / 即将到期 / 需要处理”聚合。单条可完成、稍后提醒或关闭，不用弹窗。 |
| 后台任务 | 导入、解析、索引、备份在顶栏任务指示器显示进度与“查看任务”；页面可继续操作。 |
| 加载 | 初次加载用与最终布局一致的骨架，超过 300ms 显示；不以全屏转圈阻断操作。 |
| 空状态 | 一句说明 + 当前页主操作，避免插图和功能教育长文。 |
| 失败 | 就地说明原因、保留已填内容，并给出“重试”或“查看详情”；非 AI 基础功能不受 AI 不可用影响。 |
| 成功 | 行内更新为主；涉及删除、丢弃、状态拖动时，底部轻提示提供“撤销”。 |

## 2. 页面低保真

### A. Dashboard：今天

**主操作：完成一项今日行动。** 该页不放“新建”强按钮，避免把“计划”压过“执行”。

```text
┌───────────────────────────────────────────────────── 顶部焦点区 ────────────────────────────────────────────────────┐
│ 今天，先完成一件真实的事                                                                           8 月 18 日，星期二 │
│ 今日还剩 3 项待办、2 个习惯可打卡。                                                                                   │
│ ┌──────────────────────────────────── 当前行动 ────────────────────────────────────┐                              │
│ │ ○ 整理本周材料                         截止：今天                                 │                              │
│ │   这是今天最早到期的待办；完成后再决定下一项。                    [完成这项]       │                              │
│ └──────────────────────────────────────────────────────────────────────────────────┘                              │
└───────────────────────────────────────────────────────────────────────────────────────────────────────────────────┘

┌──────────────────────── 主列 ────────────────────────┬──────────────────── 次列 ────────────────────┐
│ 今日行动                                               │ 目标进展摘要                                  │
│ [待办] [习惯]（视图切换）                              │ 数值型 / 里程碑型 / 状态型各最多 1 条         │
│ ○ 给客户回复邮件                        18:00          │ 真实进度或真实状态，不展示行动换算进度        │
│ ○ 无截止日期的行动                      无截止日期      │ [查看目标]                                    │
│ 写作  [打卡] 连续 8 天  ·  拉伸 [已打卡] 连续 4 天     │                                                    │
│ [查看全部行动]                                        │ 近期到期与提醒                                │
│                                                        │ 目标将在 3 天后到期 · 2 个习惯待打卡          │
├───────────────────────────────────────────────────────┼────────────────────────────────────────────────────┤
│ 最近沉淀                                               │ 知识库状态                                     │
│ 灵感 / 决策 / 阅读记录（最多 3 条）                    │ 最近导入 2 份 · 索引中 1 份                     │
│ [查看时间线]                                          │ [进入知识库]                                    │
└───────────────────────────────────────────────────────┴────────────────────────────────────────────────────┘
```

焦点区在有当日待办时自动取最早到期的一项；若没有截止日期待办，则显示用户最近创建的一项；若均无，则变为 `今天没有待办。把一件想做的事写下来。` + 唯一 CTA `新建待办`。习惯没有内容时，仅在“今日行动”区出现 `创建习惯`文本链接。目标卡片只呈现真实进度/状态与下次记录提示，绝不显示由待办推算的完成度。

### B. 目标与行动

#### B1. 目标列表

**主操作：新建目标。** 筛选和搜索在标题下方的工具条，默认只显示“进行中”。

```text
目标                                                       [+ 新建目标]
[进行中] [已完成] [已放弃]    周期 v  度量方式 v  搜索________________
──────────────────────────────────────────────────────────────────────
健康  · 月度                    数值型
体重回到 65 kg                  66.2 / 65 kg  [真实记录进度条]
下次记录：8 月 24 日             支持行动 3 项                    >
──────────────────────────────────────────────────────────────────────
表达能力提升                     里程碑型
完成 2 / 5 个里程碑              支持行动 1 项                    >
──────────────────────────────────────────────────────────────────────
改善睡眠                         状态型
进行中，没有进度条               支持行动 0 项                    >
```

新建目标抽屉：必填“标题、周期、度量方式”；选择数值型后在同一表单出现单位/起点/目标值，选择里程碑型后出现首个里程碑输入，状态型不显示结果字段。描述、标签、到期日放在“更多信息”折叠区。空状态唯一 CTA 为 `新建目标`。

#### B2. 目标详情：共享框架

顶部显示返回“目标”、标题、周期、状态、标签；右侧弱化的更多菜单含编辑、归档/放弃。内容以“结果”优先，“支持行动”次之，明确标注二者不是因果换算。

```text
< 目标 / 健康                                  [记录数据 / 添加里程碑 / 更新状态]
体重回到 65 kg               月度 · 数值型 · 进行中
──────────────────────────────────────────────────────────────────────
结果进展（随度量方式变化）
──────────────────────────────────────────────────────────────────────
支持行动                                      [ + 新建待办 ]
项目（生活项目） 2 个    待办 3 项
```

| 类型 | 结果区低保真 | 主操作与理由 |
|---|---|---|
| 数值型 | 当前值、目标值、单位、简洁趋势线、数据点时间线；空时显示“尚无真实记录” | `记录数据` 放在结果区右上，是唯一能改变进度的操作；录入弹层仅“数值、日期”，备注折叠。 |
| 里程碑型 | 可勾选清单、`已完成 2/5`、新增输入行；无进度趋势图 | `添加里程碑` 放在列表右上；勾选行内立即更新真实完成数，排序由拖拽手柄而非复杂管理页完成。 |
| 状态型 | 大状态标识、开始/更新时间、简短说明；**没有进度条** | `更新状态` 打开三项菜单（进行中/已完成/已放弃），避免用伪精确数据。 |

“支持行动”始终展示：生活**项目**使用浅青色圆角标签和`文件夹/路线`图标；待办使用中性复选框。`+ 新建待办`预填当前目标，但可取消关联。项目的新建/编辑收在支持行动区菜单，不与结果区主操作争抢。

#### B3. 待办列表

**主操作：新建待办。** 列表按截止时间固定排序：今天、未来 7 天、之后、无截止日期、已完成；无优先级、四象限或颜色威胁。

```text
待办                                                       [+ 新建待办]
[全部] [未完成] [已完成]    截止日期 v   目标 v   项目 v   搜索________
今天
  ○ 整理本周材料                       今天   [目标名（可选）]
未来 7 天
  ○ 预约体检                           8/20
无截止日期
  ○ 更新简历                           [生活项目：求职准备]
```

新建待办右侧抽屉默认仅有“待办名称、截止日期（可留空）”；`关联目标或生活项目`为折叠行，展开后两个选择器均默认空。保存后任务即时出现在对应截止日期组。行菜单含编辑、设置进行中、删除；完成通过最左复选框，不增加额外确认。

#### B4. 习惯

**主操作：今日打卡。** 创建习惯只是页首次级按钮，避免把维护习惯本身变为目的。

```text
习惯                                           [+ 创建习惯]
今天
写作                 连续 8 天    最近 7 天  · · · · · · ·       [打卡]
拉伸                 连续 4 天    最近 7 天  · · · · · · ·       [已打卡]
──────────────────────────────────────────────────────────────────────
全部习惯
阅读                 每周 3 次    本周 1/3                      >
```

点击 `打卡` 后原地变为“已打卡”，只提示可撤销；不出现庆祝动画或分数。创建抽屉只需“名称、频率（每日/每周次数）”，备注折叠。习惯详情由点击行进入，展示日历式历史和连续天数，但不以缺卡红色警告制造压力。

### C. 知识与沉淀

#### C1. 知识库

**主操作：导入资料。** `撰写文章`与`新建 Prompt`放在主按钮的下拉菜单中，主按钮将导入、选择文件、导入进度串成一条清楚路径。

```text
知识库                                                     [导入资料 v]
搜索标题、正文、标签_________________  类型 v  标签 v  索引状态 v
──────────────────────────────────────────────────────────────────────
标题                         类型       标签              更新时间/索引
《如何做周复盘》             Markdown   复盘              今天  就绪
沟通技巧整理                 PDF        工作              昨天  索引中 62%
周报 Prompt                  Prompt     写作, 周报         8/10  就绪 [复制]
```

“导入资料”菜单：`选择文件`、`从收藏箱剪藏`、`撰写文章`、`新建 Prompt 模板`。选择文件后，任务面板展示“解析、分块、索引”三段状态，失败可在行内 `重试索引`，不阻塞保存或关键词搜索。文档详情采用三栏：元数据/正文/来源与索引状态；引用跳转默认定位到正文片段并高亮。

空状态：`这里保存值得反复找到的资料。` + `导入资料`。索引不可用时保留全文搜索并显示非阻断条幅：`语义索引暂不可用，仍可按关键词检索。`

#### C2. 收藏箱

**主操作：保存收藏。** 列表只展示待处理项；已剪藏、仅保留、已丢弃移至状态筛选，不占默认注意力。

```text
收藏箱                                                     [+ 保存收藏]
[待处理] [已处理]  类型 v  搜索_________________
──────────────────────────────────────────────────────────────────────
文章标题 / 链接
一段备注或保存的片段摘要                      今天
                                  [剪藏入库] [仅留链接] [更多 v]
```

保存抽屉最小字段为“链接或片段、标题”；备注折叠。处理动作只在悬停或选中时出现，`剪藏入库`是单项的主动作；完成后条目淡出并提供撤销。若抓取失败，保留链接、提示可“仅留链接”或“重试抓取”。

#### C3. 问答（RAG）

**主操作：提问。** 输入框固定在对话底部，不设置“自动扩展其他个人数据”的默认开关。

```text
问答                                      [仅知识库 v]
──────────────────────────────────────────────────────────────────────
你：我有没有写过适合周报的 prompt？

回答：根据已索引资料，下面这个模板适合…… [1] [2]

引用来源
[1] 周报 Prompt  > 模板结构                         查看原文片段 >
    “本周完成了……下周需要……”
[2] 《如何做周复盘》 > 第 3 节                        查看原文片段 >

──────────────────────────────────────────────────────────────────────
输入你的问题_______________________________________________ [发送]
```

每个回答必须有可点击引用编号；点击在右侧抽屉打开“文档标题、来源、定位信息、上下文片段”，可跳转到全文。回答生成时显示“正在检索资料”再显示“正在组织回答”，可停止；没有依据时必须回答“不知道”，并展示相似资料而不是编造。无 LLM 时保留查询与相似资料列表，明确说明“当前无法生成回答”。

#### C4. 沉淀时间线

**主操作：记录此刻。** 新建菜单按“日记、灵感、决策、阅读、周复盘”分流；默认最新在前。

```text
沉淀时间线                                                [+ 记录此刻 v]
全部  日记  灵感  决策  阅读  复盘      关联实体 v  搜索____________
──────────────────────────────────────────────────────────────────────
今天
灵感  | 标题 / 内容摘要                                    10:22
      | #写作  关联：开发项目「人生系统」
      | [升格为知识库]  [更多]
昨天
决策  | 为什么选择……
```

普通记录抽屉先要求“类型、内容”，标题和关联实体为折叠字段。选择“周复盘”后进入固定三问模板：`本周发生了什么？/ 我学到了什么？/ 下周想调整什么？`，关联实体放在模板下方的折叠区。升格为知识库不离开时间线：点击后小浮层选“原样升格 / 编辑后升格”；成功后条目保留，显示“已升格”与文档链接，后台索引进度进入任务面板。

### D. 心理健康

#### D1. 情绪记录

**主操作：记录这次情绪。** 不是每日例行打卡，页面不显示“连续记录”。

```text
记录情绪                                                   [查看本周回顾]
这次更接近哪种感受？
搜索情绪词__________________  [惆怅] [遗憾] [被背叛] [焦躁] [+ 自定义]

强度  1   2   3   4   5       （离散五档按钮，不是滑杆）
发生了什么？
____________________________________________________________

▸ 补充情境与需求（可选）

                                                     [保存记录]
──────────────────────────────────────────────────────────────────────
最近记录
8/16  惆怅 · 3/5  事件摘要                                      >
```

表单在同页主列完成，减少弹层带来的情感距离。`情境（地点/和谁）`与`此刻需要什么`默认收起；用户需要时才展开。保存后显示一条中性确认，并将记录加入下方时间序列。词库支持搜索、多级分类和自定义词；“强度”只描述当次体验，不以正负色彩评判。

空状态：`只有明显情绪波动时，才需要在这里留下一笔。` + 聚焦情绪词搜索。AI 不可用不影响记录保存。

#### D2. 情绪周报

**主操作：生成本周回顾。** 生成是用户发起，系统不推送催促。

```text
情绪周报                                     8/12 - 8/18   [生成本周回顾]
──────────────────────────────────────────────────────────────────────
本周记录概览
记录 4 次 | 常见感受：惆怅、焦躁 | 强度中位数：3
[情绪词分布（条形图）]       [强度趋势（折线图）]

AI 回顾
记录显示……（说明数据范围与非诊断提示）
观察到的模式
可以尝试的下一步
```

不足两条记录时，不提供推断，只说明“记录还不足以形成回顾”。生成时显示数据范围、加载进度和可取消状态；失败时保留统计图与上一次报告，提供重试。报告使用“记录显示”“你似乎”等不确定措辞，禁止诊断和强制建议。

### E. 项目交付

#### E1. 想法收集

**主操作：记下想法。** 低门槛收集优先于评估，默认视图为“收集”。

```text
想法收集                                                   [+ 记下想法]
[收集] [评估中] [可立项] [已立项] [已放弃]    搜索____________
──────────────────────────────────────────────────────────────────────
人生系统移动端              今天
一句描述……                  [开始评估]
──────────────────────────────────────────────────────────────────────
阅读助手                    昨天
价值：4/5  可行性：3/5       [立项为开发项目]
```

新建抽屉只需“标题、描述”。`开始评估`后同页展开价值、可行性两个 1-5 离散选项与评估备注，未完成评估不可出现立项按钮。`立项为开发项目`打开确认抽屉，预填名称和描述、允许设置首阶段；成功后想法标记已立项并链接新开发项目。

#### E2. 开发项目看板

**主操作：推进开发项目。** 页面按可自定义阶段分组；不要把“新建项目”“管理阶段”都做成同级高对比按钮。

```text
开发项目                                       [阶段设置] [ + 新建开发项目]
──────────────────────────────────────────────────────────────────────
需求 (2)                 开发 (3)                测试 (1)      交付 (0)
┌─────────────────┐     ┌─────────────────┐     ┌───────────┐
│ 人生系统        │     │ 知识整理工具    │     │ 记账工具  │
│ 最近更新 今天    │     │ 最近更新 昨天   │     │ 8/15      │
│  ◉ 需求         │     │  ◉ 开发         │     │  ◉ 测试   │
└─────────────────┘     └─────────────────┘     └───────────┘
```

拖动卡片时显示来源列占位和目标列高亮；放下后卡片先原地确认状态，底部轻提示 `已移至“测试”｜撤销`。键盘替代：卡片更多菜单提供 `移动到阶段`，并支持 `Space` 抓取、方向键选列、`Enter` 放置。`阶段设置`进入右侧抽屉，支持重命名、排序、新增、设为终点；删除含项目的阶段必须先迁移项目。这里的**开发项目**统一用靛蓝色阶段点和`代码方框`图标，与生活项目的青绿色文件夹图标分开。

#### E3. 开发项目详情

**主操作：推进到下一阶段。**

```text
< 开发项目 / 人生系统                       [推进到「开发」]
人生系统     开发项目 · 活跃     仓库链接（可选）
需求 ━━━━━━━●━━━━━━━━━━ 开发 ───────── 测试 ───────── 交付
──────────────────────────────────────────────────────────────────────
项目说明
……

阶段历史
8/18  进入需求
```

阶段条只显示状态流，不伪装成任务完成进度。到达终点阶段时主操作变为`完成开发项目`并二次确认；暂停/归档/编辑位于更多菜单。无仓库、无描述时使用就地添加链接，不让空字段制造大面积空卡。

### F. 设置

**主操作：保存当前设置。** 设置采用左侧二级导航、右侧单一设置面板；连接、备份等具有独立风险的操作在对应小节内成为唯一强操作。

```text
设置
┌──────────────┬──────────────────────────────────────────────────────┐
│ 数据源与 AI  │ 数据源与 AI                                           │
│ 提醒与降噪   │ MySQL   未连接 / 已连接 · 最近检测时间                │
│ 数据安全     │ 连接信息（默认收起） [测试连接]                       │
│ 外观与辅助   │ Milvus  健康 / 异常  [测试连接]                       │
│              │ LLM 服务 [已配置 / 未配置]  数据将发送范围说明        │
│              │                                      [保存设置]       │
└──────────────┴──────────────────────────────────────────────────────┘
```

| 二级页 | 内容与主操作 |
|---|---|
| 数据源与 AI | MySQL、Milvus 连接状态与测试；LLM 密钥、模型、数据发送范围说明。连接字符串与密钥默认遮蔽，测试结果就地显示。主操作：`保存设置`。 |
| 提醒与降噪 | 三级主动性分组开关和频率：关键提醒默认开、周期报告默认生成不打扰、主动推荐默认关。主操作：`保存提醒偏好`。 |
| 数据安全 | 上次备份、备份位置、导出入口、恢复入口。主操作：`立即备份`；恢复单独危险区，先校验备份清单、说明将替换当前数据，再二次确认。 |
| 外观与辅助 | 浅色/深色/跟随系统、减少动态效果、字号密度、键盘快捷键说明。主操作：`保存外观偏好`。 |

## 3. 关键交互规格

| 流程 | 交互与状态 |
|---|---|
| 新建待办 | 当前页右上 `新建待办` → 右侧抽屉 → 输入标题和可选截止日期 → 可展开关联 → 保存 → 插入按截止日期排序的位置并短暂高亮。标题为空时按钮禁用并行内提示。 |
| 数值目标记录 | `记录数据` → 小弹层填写数值与日期，备注折叠 → 保存 → 当前值、进度、趋势同步更新。数值跨越目标时提示“已达到目标值”，由用户决定是否将状态改为完成。 |
| 习惯打卡 | 单击 `打卡` → 行内切换 `已打卡` 和连续天数 → 4 秒撤销提示；重复打卡不新增记录。 |
| 沉淀升格 | 条目 `升格为知识库` → 选原样/编辑 → 建立文档并保留时间线记录 → 任务面板显示解析和索引。完成时出现文档链接；失败时不影响原条目。 |
| 看板拖动 | 拖起卡片 → 目标列高亮 → 放置 → 立即更新阶段并出现撤销；离开页面后任务状态仍已保存。提供菜单与键盘替代，绝不要求拖动才能完成操作。 |
| RAG 问答 | 输入问题 → 检索状态 → 生成状态 → 带编号引用回答。引用打开原文抽屉；无证据则明确说明，没有引用的内容不可显示为确定回答。 |

## 4. 视觉方向（待选择）

| 方向 | 核心气质 | 适用与取舍 | 建议 |
|---|---|---|---|
| A. 素净文字优先 | 近白底、深墨文字、低饱和松石绿作为行动色；用留白、排版和细分隔线建立层级 | 最符合“镜子”定位；长文、知识引用、真实数据最清晰。缺点是需要靠良好排版而非装饰建立记忆点。 | **推荐** |
| B. 温和记录感 | 柔白底、灰紫与砖红为小面积情绪和记录色；时间线更有纸张感 | 更适合自我回顾和情绪模块；若全局使用，容易把开发项目和数据设置变得不够工具化。 | 可作为 A 的情绪模块局部变体 |
| C. 冷静工具型 | 中性灰底、蓝灰结构色、信息密度略高、表格和看板更强 | 开发项目、设置和知识库效率高；整体更像生产力工具，可能削弱反思与记录的安全感。 | 不推荐作为全局方向 |

**推荐决策：选择 A，并在心理健康区引入 B 的一小组辅助色。** 这能维持产品整体的克制，同时让“情绪”在不夸张的前提下被清楚辨认。

## 5. 组件与视觉系统（结构规格）

以下为高保真前可冻结的组件行为；具体色值在视觉方向确认后定稿。

### 5.1 设计令牌

| 类别 | 规格 |
|---|---|
| 字体 | 中文：`Noto Sans SC` 或系统无衬线；数字使用等宽数字特性。正文 14px/22px；表单和列表 14px；页面标题 24px/32px；区块标题 16px/24px；辅助信息 12px/18px。 |
| 间距 | 4px 基础格；常用 4/8/12/16/24/32/48。 |
| 圆角 | 控件 6px、卡片 8px、标签 999px；避免大圆角造成消费产品感。 |
| 阴影 | 默认无阴影；浮层/抽屉仅一档柔和阴影。用边框和空间而非卡片堆叠分区。 |
| 动效 | 150-220ms，限状态切换、抽屉、拖放反馈；无装饰性入场，尊重“减少动态效果”。 |
| 对比度 | 正文与背景至少 4.5:1；状态必须用图标/文本与颜色共同表达。 |

### 5.2 色彩语义（候选 A）

| Token | 用途 | 候选值 |
|---|---|---|
| `surface.canvas` | 页面底色 | `#FAFBF9` |
| `surface.panel` | 列表、抽屉、输入区 | `#FFFFFF` |
| `text.primary` / `text.secondary` | 正文 / 辅助 | `#1F2927` / `#66716E` |
| `border.subtle` | 分隔、输入边框 | `#DDE3E0` |
| `action.primary` | 唯一主操作、当前导航 | `#0F766E` |
| `knowledge` | 知识库、引用 | `#2563EB` |
| `wellbeing` | 情绪标签、周报辅助标识 | `#B4536A` |
| `life-project` | 生活项目图标与标签 | `#0F766E` |
| `dev-project` | 开发项目图标与标签 | `#4F46A5` |
| `status.success/warn/danger` | 完成 / 需注意 / 失败 | `#2F7D4B` / `#A15C00` / `#B42318` |

### 5.3 核心组件

| 组件 | 规格 |
|---|---|
| 主按钮 | 每页至多一个高对比主按钮，右上固定位置；高度 36px，带可见加载与禁用态。 |
| 次级按钮 / 图标按钮 | 次级用描边或文字，工具动作用图标按钮并有悬停提示和无障碍名称。 |
| 输入与选择器 | 始终有可见标签；高度 36px；错误紧随字段下方。高级字段用带箭头的展开行，不用一开始堆满表单。 |
| 抽屉 | 新建与编辑用右侧抽屉，宽 480px；标题固定，内容可滚，底部固定取消/保存。离开未保存时确认。 |
| 列表行 | 左侧动作、主体、元信息、尾部更多菜单四段；完成/索引/状态均可在不打开详情时读懂。 |
| 卡片 | 仅用于可独立扫描的目标摘要、看板项目、提醒；不把全页面区块包成悬浮卡。 |
| 标签 | 仅表示周期、类型、关联或状态，不承载“优先级”；文本与图标共同区分生活项目、开发项目。 |
| 引用块 | 编号、文档名、定位、原文片段、打开原文动作缺一不可；引用编号在回答正文中可点击。 |
| 空状态 | 最大 2 行说明 + 当前页主操作；不使用夸张插画或责备语言。 |

## 6. 待确认项

| 待确认项 | 推荐 | 原因 |
|---|---|---|
| 全局视觉方向 | 选 A“素净文字优先”，情绪模块局部采用 B 的辅助色 | 最贴合“克制、本地、诚实”，且支持知识库长内容阅读。 |
| 生活项目入口 | 首版不在侧栏单列“项目”，只在目标详情支持行动区和待办筛选出现 | 生活项目是可选容器；单列入口会提高导航复杂度，也更容易与开发项目混淆。若 CRUD 频率很高，可在“目标”页提供页签入口。 |
| 全局搜索范围 | 默认搜索知识库与页面内数据，不聚合情绪内容 | 遵守情绪独立与隐私边界；情绪记录只在自身页面内查询。 |
| 提醒入口 | 顶栏提醒抽屉，Dashboard 只显示摘要 | 既保证可见性，又避免将 Dashboard 变成通知中心。 |
| 主题 | 首版提供浅色、深色、跟随系统；高保真先完整出浅色主稿 | 使用场景包含夜间记录与长时间阅读；但当前视觉基调明确为浅色优先。 |
