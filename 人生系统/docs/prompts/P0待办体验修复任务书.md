## 五、实现要求

### 5.1 新建表单校验 + 反馈（R-1）

- `el-form` 绑定 `ref` + `:model` + `:rules` + `label-position="top"`：
  - `title`：`[{ required: true, message: "请输入标题", trigger: "blur" }]`（与服务端 `min(1).max(100)` 一致）
  - `note`：`max: 2000`（对齐 `optionalText`）；`dueDate` 无额外规则（可选）
- 标题 label 加必填标记（`required` 或 `*`）；保存按钮 `:loading="saving"`，点击先 `formRef.validate()` 通过再提交
- 失败：`call` 内部已弹 toast，页面 catch 后**保持弹窗打开、输入不丢**；成功：`ElMessage.success("待办已创建")` → 关弹窗 → 刷新

### 5.2 完整编辑弹窗（R-2）

- 移除 `ElMessageBox.prompt` 仅改标题的做法，**新建/编辑共用同一 `el-dialog` 表单**：
  - 新建：空表单，标题「新建待办」
  - 编辑：回填全部字段（`title`/`note`/`dueDate`/`goalId`/`projectId`），标题「编辑待办」；提交走 `tasks.update`（**全字段传真实值**，不得清空未展示字段）
- 编辑保存成功 `ElMessage.success("已保存")` → 关弹窗 → 刷新

### 5.3 写操作统一反馈（R-3，贯穿）

- 所有 `async` 处理器（`save`/`transition`/`edit`/`remove`）加 `try/catch`：catch 内不重复弹 toast（`call` 已弹），只负责**保持 UI 状态**（弹窗不关、loading 复位、表单不清空）
- 成功路径统一 `ElMessage.success`（创建/编辑/删除/开始/完成/撤销完成各自文案）
- `saving` 状态 `finally` 复位

### 5.4 删除确认取消捕获（R-4）

- `remove()` 的 `ElMessageBox.confirm` **取消分支 catch**（`try { await confirm } catch { return }`），取消时静默返回；确认后删除成功 `ElMessage.success("已删除")`
- 不再出现取消弹窗时的 UnhandledPromiseRejection

### 5.5 状态流转防重复（R-5）

- `transition()` 进行中：对应按钮 `loading` 或整行禁用，防止快速连点并发触发
- 可加简单 `busy` 集合（`transitioningIds`）管理单行 loading；完成后清除并刷新

### 5.6 筛选增强（R-6）

- 工具栏在状态筛选旁增加：
  - **按目标筛选**：`el-select`（选项=已加载 goals，`clearable`，placeholder「按目标」）
  - **按项目筛选**：`el-select`（选项=已加载 projects，`clearable`，placeholder「按项目」）
  - **日期范围**：`el-date-picker type="daterange"`（值映射为 `dateFrom`/`dateTo` UTC，`clearable`）
- `load()` 组装筛选参数 `{ status, goalId, projectId, dateFrom, dateTo, sort }` 传给 `tasks.list`（无值不传）；任一筛选变化 → `load`
- 空结果文案区分"当前筛选下没有待办"（已有）与"还没有待办"（全量空）

### 5.7 逾期感知（R-7）

- 列表行：`item.status !== "done"` 且 `dueDate` 早于当前时间 → 截止时间显示红色 + 行前「已逾期」标记（如 `el-tag type="danger" size="small"`）
- 数据以 `new Date(item.dueDate) < new Date()` 本地比较（时间展示本就是本地化）

### 5.8 列表元信息可读性（R-8）

- 状态/时间/目标/项目分行或分段展示（如时间一行、关联目标/项目一行），逾期标记独立；减少单行拥挤
- 不改变数据来源与排序逻辑
