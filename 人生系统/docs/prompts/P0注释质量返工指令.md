# P0 注释质量问题返工指令（第三轮 · 专项）

> 角色：你是一名对自己代码可读性负责的 TypeScript 工程师。本轮**只做一件事：清除注释注水，把注释写成真注释**。除注释外不修改任何代码逻辑。

> 工程根目录：`life-system/`。改动范围：仅 `src/` 下的 `.ts` / `.vue` 文件注释；**禁止**改动任何业务逻辑、schema、配置、脚本。

---

## 一、背景：上一轮返工把注释灌水了（先说清楚问题）

上一轮为了达成"注释占比 ≥15%"的指标，在代码里复制粘贴了大量模板句。实锤数据：

- 全文出现 **6 类模板句共 751 处，占全部 819 行注释的 92%**。
- 典型症状（**都与代码语义冲突，会误导读者**）：
  - 渲染层 Vue 函数被标 `// 这里执行持久化或事务步骤……` ——渲染层没有事务；
  - 领域纯函数 `streak.ts` / `state-machines.ts` 被标 `// 封装这个业务步骤，保证规则在主进程集中执行……` ——纯函数不在主进程执行；
  - `import` 语句旁、SQL 字符串常量旁挂着"确保数据库事实与界面状态保持一致"。

指标骗过了统计脚本，但骗不过人。**本轮指标让位于质量**：占比允许下降，但每一条注释都必须真实、具体、可独立读懂。

---

## 二、禁令：以下 6 句及任何同义变体，全文一律删除

1. `// 这里执行持久化或事务步骤，确保数据库事实与界面状态保持一致。`
2. `// 显式处理当前状态分支，非法路径必须返回可操作的结构化错误。`
3. `// 将结果交给上层或抛出带错误码的失败，避免调用方误把失败当成功。`
4. `// 封装这个业务步骤，保证规则在主进程集中执行并可由单元测试覆盖。`
5. `// 保存当前业务事实或派生值，后续逻辑据此完成校验和状态更新。`
6. `// 所有界面动作经窄 API 或原生对话框执行，避免渲染层越过进程边界。`

**删除方式**：先删掉该模板句本身；再看它所在的那行代码**是否真有值得写的业务语义**——
- 有 → 用 §三 的方法写一条真实注释；
- 没有（如 `import`、普通 `return`、显而易见的赋值）→ **直接不写**，允许该处回到无注释状态。

禁止任何"改几个字重排一遍模板句"的变体替换（如把"持久化或事务步骤"改成"数据处理步骤"再贴 50 处，同样违规）。

## 三、替换方法论 + 4 个对照示范（照此标准写）

每条注释必须能独立回答「**这段代码在做什么、为什么这么做**」，且不得与代码所处层级冲突。下面是就在你工程里抓的 4 组真实对照，直接照这个味道写：

### 示范 1 · 领域纯函数（`src/shared/domain/streak.ts`）
```ts
// ❌ 现在是：封装这个业务步骤，保证规则在主进程集中执行并可由单元测试覆盖。
function mondayOf(localDate: string): string {
  const date = new Date(`${localDate}T00:00:00Z`);
  const day = date.getUTCDay() || 7;        // ✅ 应为：getUTCDay() 周日返回 0，转成 7 才能让"减到周一"的算法统一生效
  date.setUTCDate(date.getUTCDate() - day + 1);
  return date.toISOString().slice(0, 10);   // ✅ 应为：星期一作为"自然周"的键，跨周统计都靠它分组
}

// ❌ 现在是：显式处理当前状态分支，非法路径必须返回可操作的结构化错误。
if (dateValue(days[index - 1]!) - dateValue(days[index]!) !== 86_400_000)
  break;                                      // ✅ 应为：相邻打卡严格相隔 1 天（86.4 万毫秒）才延续连续天数，跳天即断开
```
> 说明：`streak.ts` 里已经存在的真实注释（如"只有相邻自然日才延长连续天数""连续达标周的周一必须正好相差七天"）是合格的，**保留**；只清理它旁边的模板句。

### 示范 2 · 状态机（`src/shared/domain/state-machines.ts`）
```ts
// ❌ 现在是：封装这个业务步骤，保证规则在主进程集中执行并可由单元测试覆盖。
export function transitionProject(current: string, target: string): void {
  // active 与 paused 可互转，二者都可结束；done 不允许恢复。（✅ 这条保留）
  const allowed: Record<string, string[]> = { active: ["paused", "done"], paused: ["active", "done"], done: [] };
  if (!allowed[current]?.includes(target))
    throw Object.assign(new Error("项目状态转换不合法"), { code: "INVALID_STATE" });
    // ✅ 应为：paused/done 不在 allowed 表里，越权转换直接抛 INVALID_STATE，由 IPC 层转成结构化错误返回界面
}
```
> 说明：`allowed` 映射即"转换合法表"，注释应点破"表外即违法"这一设计，而不是 4 行后补一句废话。

### 示范 3 · 服务层进度计算（`src/main/modules/goals/service.ts`）
```ts
let progress: number | null = null;
// ❌ 现在是：显式处理当前状态分支，非法路径必须返回可操作的结构化错误。
if (goal.metricType === "numeric")             // ✅ 应为：数值型目标用最新一条记录当当前值算进度；无记录视为尚未开始
    progress = calculateNumericProgress(...);
// ❌ 现在是：显式处理当前状态分支，非法路径必须返回可操作的结构化错误。
if (goal.metricType === "milestone")           // ✅ 应为：里程碑型按已完成里程碑数 / 总里程碑数算进度
    progress = calculateMilestoneProgress(...);
```
> 说明：每类进度计算"用什么数据、什么公式"才是读者想知道的，恰好这两个分支的差异就是业务规则本身。

### 示范 4 · 渲染层（`src/renderer/features/settings/SettingsPage.vue`）
```ts
// ✅ 已有真实注释「恢复会覆盖当前数据库，先由用户明确确认，取消时不发送 IPC。」——保留
let action: string;
try { action = await ElMessageBox.confirm(...) } catch { return; }
if (action !== "confirm") return;
// ❌ 删除这一行：显式处理当前状态分支，非法路径必须返回可操作的结构化错误。
try {
    const result: any = await call(() =>
      window.lifeSystem.backup.restore({
        manifestPath: "SELECT",   // ✅ 应为：SELECT 是主进程约定的哨兵值，触发原生文件选择对话框
        confirmation: "恢复",      // ✅ 应为：restoreSchema 要求字面量"恢复"，防止手滑误恢复
      }),
    );
```
> 说明：渲染层注释只写"界面行为/用户意图"，永远不写"事务/主进程/持久化"。

## 五、质量标准（自查时逐条过）

1. ✅ 全文搜索 6 个模板句 = 0 命中（命令见 §六）。
2. ✅ 没有"改字重排"的变体模板句（如复制 10 处"此处处理数据状态"也算违规）。
3. ✅ 每条注释独立成句，能回答"做什么+为什么"，不看上下文也能懂业务意图。
4. ✅ 注释层级正确：渲染层不提事务/主进程/持久化；纯函数不提"持久化或业务步骤"。
5. ✅ 每个模块至少 1 条"画龙点睛"注释：解释该文件核心设计（如 goals 的 `decorateGoal` 为何要把 tags/records/milestones 一次性查齐组装），放在模块顶部或关键函数上方。
