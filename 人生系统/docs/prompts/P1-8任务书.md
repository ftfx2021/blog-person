```sql
-- 人生系统 P1-8：AI 助手体系（助手/会话/消息），沿用 InnoDB + utf8mb4 + UTC DATETIME(3)。
CREATE TABLE ai_assistant (
  id CHAR(36) NOT NULL COMMENT '助手 UUID',
  name VARCHAR(50) NOT NULL COMMENT '助手名称',
  description VARCHAR(200) NULL COMMENT '助手简介',
  system_prompt TEXT NOT NULL COMMENT '系统提示词（本期唯一模型配置）',
  model_config_json JSON NULL COMMENT '未来：每助手模型设置，本期不启用',
  knowledge_base_id CHAR(36) NULL COMMENT '未来：关联知识库，本期不启用',
  created_at DATETIME(3) NOT NULL COMMENT '创建时间（UTC）',
  updated_at DATETIME(3) NOT NULL COMMENT '更新时间（UTC）',
  PRIMARY KEY (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='AI 助手';

CREATE TABLE ai_session (
  id CHAR(36) NOT NULL COMMENT '会话 UUID',
  assistant_id CHAR(36) NOT NULL COMMENT '所属助手',
  title VARCHAR(100) NOT NULL DEFAULT '新会话' COMMENT '会话标题',
  created_at DATETIME(3) NOT NULL COMMENT '创建时间（UTC）',
  updated_at DATETIME(3) NOT NULL COMMENT '更新时间（UTC）',
  PRIMARY KEY (id),
  KEY ix_ai_session_assistant (assistant_id, updated_at DESC),
  CONSTRAINT fk_ai_session_assistant FOREIGN KEY (assistant_id) REFERENCES ai_assistant(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='AI 会话';

CREATE TABLE ai_message (
  id CHAR(36) NOT NULL COMMENT '消息 UUID',
  session_id CHAR(36) NOT NULL COMMENT '所属会话',
  role VARCHAR(16) NOT NULL COMMENT '消息角色：user/assistant',
  content MEDIUMTEXT NOT NULL COMMENT '消息内容',
  created_at DATETIME(3) NOT NULL COMMENT '创建时间（UTC）',
  PRIMARY KEY (id),
  KEY ix_ai_message_session (session_id, created_at),
  CONSTRAINT fk_ai_message_session FOREIGN KEY (session_id) REFERENCES ai_session(id) ON DELETE CASCADE,
  CONSTRAINT ck_ai_message_role CHECK (role IN ('user', 'assistant'))
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='AI 会话消息';
```

- 迁移目录已有 `001_initial_schema.sql`（P0 全量基线，**不动**）；runner 按文件名序自动执行新文件
- 软删除不用于 AI 助手（删除即硬删 + 级联）；索引与 CHECK 如上，不做额外设计

### 5.3 Assistant 服务（新建 `src/main/modules/assistant/service.ts`）

```ts
// 统一用 requirePool() 直连；时间用既有 utcNow()；UUID 用 randomUUID()。
export const assistantService = {
  list: async (): Promise<AssistantRow[]>               // 全部助手，按 updated_at DESC
  create: async (input)                                 // 校验 → 落库 → 返回行
  update: async (input)                                 // 至少一项变更；更新 updated_at
  remove: async (id)                                    // 删除助手（会话/消息级联由 FK 处理）
  sessions: async (assistantId)                         // 会话列表按 updated_at DESC
  createSession: async (assistantId)                    // title='新会话' → 返回行
  renameSession: async (id, title)
  removeSession: async (id)
  messages: async (sessionId, limit, offset)            // 返回 { messages, total }，按 created_at ASC
  appendMessage: async (sessionId, role, content)       // 落库一条消息；user 消息触发自动命名（见下）
  autoTitle: async (sessionId, content)                 // 若标题仍为"新会话"且 content≥3 字，取前 20 字为标题
};
```

- **自动命名规则**（决策 A2）：`appendMessage` 收到 role=user 时，若该会话 title 仍为 `新会话` 且消息 ≥ 3 字 → `title = content.slice(0, 20)`，并更新 `updated_at`
- **消息读取**：`SELECT ... WHERE session_id=? ORDER BY created_at ASC LIMIT ? OFFSET ?`，另查 `COUNT(*)` 作 total；服务层把 DESC 取最近再反转，保证页面上旧在下新在上
- **会话 updated_at**：新建消息、重命名时更新；会话列表按此排序（最近活跃置顶）
- 所有方法失败抛结构化错误（复用 `failure()` 风格）：找不到实体 → `NOT_FOUND`；删除助手/会话前校验存在

### 5.4 ChatService 改造（`src/main/modules/chat/service.ts`）

保留：流式骨架（AbortController、`ai:chat:delta/reasoning/done/error` 事件、停止、`CONFLICT` 防并发）。**删除**：`sessions` Map 历史存储、`trimHistory` 之外的部分逻辑。

**start 流程**：
1. 入参 `{ sessionId, message }`（DB 会话 UUID）；`active` Map 仍有该会话 → `CONFLICT`（沿用）
2. 加载会话 + 所属助手：`ai_session` + `ai_assistant` 联查；任一不存在 → `NOT_FOUND`
3. **落库用户消息**：`assistantService.appendMessage(sessionId, "user", message)`（内部触发自动命名）
4. **构造上下文**（简单版，决策 A3）：
   - `const context: ChatMessage[] = []`
   - 助手 `system_prompt` 非空 → `context.push({ role: "system", content: system_prompt })`
   - 查该会话**最近 20 条**历史（含刚落的 user 消息），按时间序 push（`role: "user" | "assistant"`）
5. 流式请求（沿用 `provider.chatStream`）：增量事件照发；`active.text` 累计
6. **收尾**（成功或中止）：
   - `active.text` 非空 → `assistantService.appendMessage(sessionId, "assistant", active.text)`（**中止时已生成部分也入库**，决策 A4）
   - 发 `ai:chat:done`（含 `aborted`）
7. **失败回滚**（决策 A4）：异常/未配置 LLM → **删除本轮 user 消息**（按 message 内容 + session 最近一条匹配删除），发 `ai:chat:error`；错误码映射沿用现有 `sendError`

**要点**：
- 上下文构建以 DB 为准；`MAX_MESSAGES = 20` 常量保留为「历史条数上限」
- 渲染层 `sessionId` 即 `ai_session.id`，无需再回传；start 返回值 `{ sessionId }` 不变（兼容现有页面调用）
- `stop` 逻辑不变

## 九、技术决策（已锁定，直接执行）

| 项 | 决策 |
|---|---|
| 持久化 | 三张新表 `ai_assistant`/`ai_session`/`ai_message`；会话与历史落库；内存 Map 仅存流式活动会话 |
| 助手配置 | 本期仅 name/description/system_prompt；`model_config_json`/`knowledge_base_id` 建列不启用 |
| 上下文 | system prompt + 最近 20 条历史；超出丢弃最旧（简单版） |
| 落库时机 | 用户消息发送即落库；助手回复完成（含中止部分）后落库；LLM 失败回滚本轮用户消息 |
| 自动命名 | 会话标题默认「新会话」；首条用户消息 ≥3 字且未改名 → 取前 20 字 |
| 模型来源 | 全局 LLM 配置（`settingsService.getActiveChatConfig`，P1-1）；不改设置页 |
| 删除语义 | 删除即硬删 + FK 级联；不软删、无回收站 |
| 分页 | `session:messages` limit+offset；默认最近 50 条 |

## 附录 A：自动命名与回滚的边界（实现对照）

- `autoTitle` 只在 `appendMessage(sessionId, "user", ...)` 内触发，避免独立调用点遗漏；`UPDATE ai_session SET title=?, updated_at=? WHERE id=? AND title='新会话'`
- 失败回滚删除用户消息时：`DELETE FROM ai_message WHERE id=(SELECT 最近一条 session_id=? AND role='user' AND created_at=(SELECT MAX(created_at)...))`——用子查询取最近一条，**不要**按 content 匹配（内容可能重复）
- 并发边界：同一会话第二次 `start` 在 `active` Map 命中即 `CONFLICT`，保证不会出现同会话两条流并行写库
