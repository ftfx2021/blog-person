## 五、实现要求

### 5.1 对话服务（`src/main/modules/chat/service.ts`）

- 会话模型：`Map<sessionId, ChatMessage[]>`（内存）。`sessionId` 用 `crypto.randomUUID()`。
- `start({ sessionId?, message })` 流程：
  1. 解析入参（经 IPC Zod 校验后）→ 取/建会话历史 → push `{role:"user", content}` → 更新会话 Map
  2. 读取已存 LLM 配置（本任务新增一个只读方法 `getActiveChatConfig()`，见 5.3，从 `app_setting` 读 `llm.chat` 解密 apiKey，构造 `LlmProviderConfig`）
  3. 无配置 → 抛 `AI_UNAVAILABLE`（"未配置 LLM"）；构造 provider → `chatStream({ messages, model, temperature:0.7, stream:true })`
  4. 逐 chunk：`type==="content"` → `webContents.send("ai:chat:delta", { sessionId, delta })`；`type==="reasoning"` → 单独事件 `ai:chat:reasoning`（可选，用于推理模型）——**不接受 reasoning 也可，但协议要能区分两种增量**
  5. 结束：`webContents.send("ai:chat:done", { sessionId, fullText })`，并把 assistant 完整回答 push 回会话历史；统计 final model
  6. 异常：`webContents.send("ai:chat:error", { sessionId, code, message })`（映射 AI_AUTH_ERROR / AI_UNAVAILABLE / INTERNAL_ERROR），不重抛导致线程崩溃
- **约束**：单个 session 同一时刻只允许一个进行中的请求（重复 start 且进行中 → 返回 `CONFLICT` 或忽略，需明确）；「停止」通过 AbortController 中断当前流，中断后正常回 `ai:chat:done`（标注 aborted）或单独 `ai:chat:stopped` 事件
- 会话历史长度上限（如 20 条），超出丢弃最旧，防 context 溢出；上限写死并用注释说明
- 所有增量经 `webContents` 推给**发起请求的窗口**（`event.sender` 对应窗口，勿广播到全部窗口）

### 5.2 IPC 与事件通道

handle 通道（`registerHandler` 注册；`chat-handlers.ts`）：

```
ai:chat:start   ← chatStartSchema { sessionId?: uuid, message: string(1..8000) } → 返回 { sessionId }
ai:chat:stop    ← chatStopSchema  { sessionId: uuid } → { stopped: boolean }
```

事件通道（`webContents.send`，渲染层经 preload 订阅）：

```
ai:chat:delta      { sessionId, delta }          # content 增量
ai:chat:reasoning  { sessionId, delta }          # 推理增量（可选订阅）
ai:chat:done       { sessionId, fullText, model?, aborted? }
ai:chat:error      { sessionId, code, message }
```

- 事件通道**不含敏感信息**（不传 apiKey、不传原始请求体）；`delta` 只含文本增量
- 主进程侧要有"事件发送失败（窗口已销毁）"的兜底，不抛未捕获异常

### 5.3 Settings 只读补充（最小改动）

- 在 `settings/service.ts` 新增只读方法 `getActiveChatConfig(): Promise<LlmProviderConfig | null>`：
  - 读 `app_setting` 键 `llm.chat`，`safeStorage.decryptString` 解出 apiKey，返回 `{ baseURL, apiKey, model, protocol }`
  - 未配置返回 `null`（不抛错），由 chat 服务判断并报 `AI_UNAVAILABLE`
  - **不修改**现有 `saveLlmConfig`/`testLlmConnection` 等已验收方法；此方法仅供 chat 服务内部使用，**不新增 IPC 暴露**
- 若不想改 settings/service.ts，也可在 chat 服务内部直接读 `app_setting` 并解密（二选一，保持 DRY 即可）。**不得**在渲染层读取明文 apiKey。

### 5.4 Preload（`src/preload/api/index.ts` 新增 `ai` 分组）

```ts
ai: {
  start: (input) => invoke("ai:chat:start", chatStartSchema, input),
  stop:  (input) => invoke("ai:chat:stop",  chatStopSchema,  input),
  // 订阅事件：只暴露固定事件名的回调注册，不暴露裸 ipcRenderer.on
  onDelta:    (cb) => subscribe("ai:chat:delta", cb),
  onReasoning:(cb) => subscribe("ai:chat:reasoning", cb),
  onDone:     (cb) => subscribe("ai:chat:done", cb),
  onError:    (cb) => subscribe("ai:chat:error", cb),
}
```
- `subscribe` 内部把 `ipcRenderer.on(channel, handler)` 包一层，并返回**取消订阅函数**（组件卸载时调用，防泄漏）；回调收到 `(event, payload)` 只取 `payload`
- 新增 schema：`chatStartSchema`、`chatStopSchema`（放 `shared/contracts/system.ts` 或新建 `shared/contracts/ai.ts`）
- 所有订阅 handler 不向渲染层暴露 `event` 对象

### 5.5 渲染层 AI 助手页（`AssistantPage.vue`）

路由 `/assistant`（name `assistant`），侧栏新增入口「AI 助手」（放知识区还是独立区由现有布局决定，侧栏加一项即可，图标沿用 Element Plus 现有 icon）。

页面结构：
- **消息区**（滚动列表）：用户气泡（右侧）/ 助手气泡（左侧）；助手消息在当前流式过程中**逐字追加**展示增量；流式结束固定为完整文本
- 空态：无消息时显示引导文案「问我任何问题」（需确认 LLM 已配置；未配置显示降级卡）
- 降级：打开页面先 `settings.getAiHealth()`，若 chat `ok:false` 显示顶部提示条「AI 不可用：{detail}」+ 引导去设置页（保留聊天 UI 但不允许发送，或允许发送但报错——建议未配置直接禁发送并提示）
- 输入区：多行输入框（Enter 发送 / Shift+Enter 换行）、发送按钮、**停止按钮**（流式中显示，点击调 `ai.chat.stop`）
- 交互：
  - 发送：本地先推一条用户消息 → 调 `ai.chat.start` 得 sessionId → 订阅该会话 delta 更新最后一条助手消息 → done/error 收尾
  - 多轮：sessionId 在首次发送后持有，后续消息沿用同一 sessionId（会话留在主进程内存，页面刷新丢 sessionId 则视为新会话）
  - 清空会话：`ai.chat.stop`（若进行中）+ 本地清空消息数组（主进程侧无显式 clear 通道，靠新 sessionId 区分——如需 clear 通道提出并记录决策）
- 状态：发送中禁用重复发送；error 显示错误气泡 + 可重试；组件卸载时取消订阅回调、若流式中调 stop
- loading/error/empty 三态齐全（沿用 P0 规范）

### 5.6 降级与错误

- `AI_UNAVAILABLE`（未配置/断网/超时后 5xx）、`AI_AUTH_ERROR`（401/403）两种错误在 UI 明确区分文案（沿用 P1-1 已加的错误映射）
- 任何 AI 异常**不影响**目标/待办/习惯等 P0 功能

## 附录 A：对话服务时序（实现对照）

```
页面发送 → preload ai.chat.start(sessionId, message)
        → IPC ai:chat:start（Zod 校验）→ chat.service.start()
           → 读 llm.chat 配置（无 → 抛 AI_UNAVAILABLE）
           → push user msg → 构造 LlmProvider → chatStream({messages, model, stream:true})
           → for await (chunk of chatStream):
                content  → webContents.send('ai:chat:delta', {sessionId, delta})
                reasoning→ webContents.send('ai:chat:reasoning', {sessionId, delta})
           → push assistant full → webContents.send('ai:chat:done', {sessionId, fullText, model})
              catch → webContents.send('ai:chat:error', {sessionId, code, message})
页面订阅 ai.chat.onDelta/onDone/onError → 更新本地消息数组
```

**异常时 session 内未完成的 user 消息不残留**（start 失败时应回滚已 push 的 user 消息，避免上下文污染——用注释说明实现方式）。
