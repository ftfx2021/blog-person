### 5.1 收藏服务（`src/main/modules/knowledge/inbox.ts`）

复用 `requirePool()`（`infrastructure/db/pool.js`）、`utcNow()`（`modules/common/database.js`）、`randomUUID()`。表 `inbox_item` 已存在（P0 迁移），字段：`id`/`kind`/`url`/`title`/`note`/`status`/`document_id`/`created_at`/`updated_at`。

```ts
export const inboxService = {
  list(input: { kind?: "link"|"snippet"|"read_later"; status?: "pending"|"clipped"|"bookmarked"|"discarded" }):
    Promise<InboxItemRow[]>,        // 按 created_at DESC
  create(input: { kind; title; url?; note? }): Promise<InboxItemRow>,
  update(input: { id; kind?; title?; url?; note? }): Promise<InboxItemRow>,
  clip(input: { id }): Promise<{ documentId: string }>,   // 剪藏入库：调 knowledgeService.clipToDocument
  keep(input: { id }): Promise<InboxItemRow>,             // 仅保留链接（bookmarked）
  discard(input: { id }): Promise<InboxItemRow>,          // 丢弃（discarded）
  restore(input: { id }): Promise<InboxItemRow>,          // 恢复（pending）
};
```

**业务规则**（FSD K01-F01~F05 + 决策 B4/B5）：
- `create` 校验：`kind` 限三种；`link`/`read_later` 的 `url` 必须是合法 http/https（`new URL()` + protocol 检查）；`snippet` 无 `url` 时必须有 `note`；`title` 必填 ≤200 字；`note` ≤2000 字；新增 `status='pending'`，**不抓取、不进 RAG**
- `update`：编辑后保持原 `status`；`kind` 变更重新校验 url/note；已 clipped 条目编辑**不得**覆盖已关联 document（只改收藏字段）
- `clip`（剪藏入库，决策 B1/B2/B4）：
  - `link`/`read_later`：调 `knowledgeService.clipToDocument({ kind, url, title, note })` → 返回 `documentId` → 事务更新 `status='clipped'`、`document_id` 回填 → 返回
  - `snippet`：**直接用 `note`（无则 `title`）作为内容**，调 `clipToDocument({ kind:'snippet', content: note||title, title })`（P1-4 真实管线将按 `doc_type=note` 处理，本期占位不区分）
  - 端口抛 `INGEST_UNAVAILABLE`（管线未就绪）时：**收藏保持 `pending` 不丢失**，向上抛该错误，UI 提示稍后重试
  - 已 clipped 条目再次 clip → `CONFLICT`
- `keep`（仅保留链接）：仅 `kind∈{link,read_later}` 合法（snippet 报 `VALIDATION_ERROR`）；`status→bookmarked`；不建 document、不进 RAG
- `discard`：仅 `pending`/`bookmarked` 可转 `discarded`；`clipped` 不允许 discard（提示先删除关联文档或仅隐藏——本期实现为拒绝并提示）
- `restore`：仅 `discarded` 可转 `pending`；**不删除**已关联 document

所有方法失败抛结构化错误（`Object.assign(new Error(), { code })`，沿用 P0 风格）：找不到 → `NOT_FOUND`；状态机非法 → `INVALID_STATE`；参数非法 → `VALIDATION_ERROR`。

## 附录 A：FSD K01 详述（原文内嵌，需求唯一依据）

> **K01-F01 存入收藏箱（P1）**
> - **入口**：收藏箱「新增收藏」。
> - **主要字段**：`kind∈{link|snippet|read_later}`；`title`（必填，≤200字）；`url`（link/read_later 推荐，snippet 可空）；`note`（可选）；`status=pending`；时间字段系统生成。
> - **业务规则**：① link/read_later 的 URL 必须是合法 http/https；② snippet 无 URL 时必须有 note；③ 新增不抓取网页、不进入 RAG。
> - **输出**：成功进入 pending 列表；失败在表单提示。

> **K01-F02 编辑收藏（P1）**
> - **入口**：收藏条目「编辑」。
> - **主要字段**：title、url、note、kind。
> - **业务规则**：编辑后保持原 status；kind 改变需重新校验 URL/note；已 clipped 条目不覆盖已生成 document。
> - **输出**：成功刷新收藏；失败不提交。

> **K01-F03 剪藏入库（P1）**
> - **入口**：pending 收藏「剪藏入库」。
> - **主要字段**：收藏 ID、可选文档标题覆盖；生成 `document` 的 `doc_type=webpage`、`source_url`、`raw_text`、`parse_status`、`index_status`；回填 `inbox_item.document_id`。
> - **业务规则**：① 仅 link/read_later 且 URL 可访问时抓取正文；② 抓取结果必须交给 K02-F10 统一入库，不得由收藏模块自行写 chunk/Milvus；③ 抓取失败保留收藏并记录 parse_status=failed（不得丢 URL）；④ 仅 MySQL 文档和 chunk 事务提交成功后，inbox status 才变为 clipped 并回填 document_id；⑤ 网页正文为空时不宣称完成剪藏。
> - **输出**：成功显示文档和索引排队状态；失败提示抓取原因并提供重试。

> **K01-F04 仅保留链接（P1）**
> - **入口**：pending 收藏「仅保留链接」。
> - **主要字段**：收藏 ID。
> - **业务规则**：仅 `kind∈{link,read_later}` 合法；将 status 置为 bookmarked；不创建 document、不进入 RAG；可再次剪藏。
> - **输出**：条目标记为 bookmarked；非法类型提示。

> **K01-F05 丢弃/恢复收藏（P1）**
> - **入口**：收藏条目「丢弃」或 discarded 列表「恢复」。
> - **主要字段**：`status∈{pending|clipped|bookmarked|discarded}`。
> - **业务规则**：pending/bookmarked 可转 discarded；discarded 可恢复为 pending；clipped 不直接丢弃文档，仅允许将收藏隐藏；恢复不删除已关联 document。
> - **输出**：成功移动分组；非法路径提示。

> 补丁（决策 B4/B5）：snippet 允许「剪藏入库」，内容=note（无则 title），`doc_type=note`，不抓取。详见 `docs/decisions/P1-收藏箱决策.md`。
