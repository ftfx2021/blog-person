## 五、实现要求

### 5.1 失效归属清理 + 加载错误态（F-1）

**根因**：`selectedFolderId` 从 localStorage 恢复后未校验，残留 id 指向已删除文件夹 → `knowledge.list` 抛错 → `load()` 无 catch → 主区空白。

`src/renderer/features/knowledge/KnowledgePage.vue`：

1. **进入页面校验并清理失效选择**：`loadBases()` 加载完文件夹树后，校验 `selectedFolderId` 是否仍存在于当前库文件夹树中（递归查找）；**不存在 → 清除**（`selectedFolderId = null`、`localStorage.removeItem("knowledge.lastFolderId")`）再 `load()`。同理 `selectedKbId` 若不在库列表（现有逻辑已有回退，确认覆盖 localStorage 更新）——保证**任何残留 id 都不会进入 list 请求**
2. **`load()` 增加错误处理**：`try/catch` + `error` ref；主区在加载失败时显示错误态（沿用项目 `PageState` 的 error/retry 模式，或等价的错误提示 + 重试按钮）；不再静默空白
3. **selectFolder/selectBase 时同步校验**：切换后若目标文件夹已被删除（如并发删除），同样回退到库根并清理存储
4. 验证语义：**页面上任何路径都不会把失效 folderId/kbId 传给 `knowledge.list`**

### 5.2 Milkdown 富文本编辑器（F-2）

依赖已装（`@milkdown/core`/`kit`/`vue` ^7.22.1），直接用 `@milkdown/vue` 的组件 + `@milkdown/kit` 的常用功能（commonmark、gfm、tooltip、列表等按 kit 默认装配），**不新增依赖**。

1. **新建手写文档弹窗**（`KnowledgePage.vue` `noteDialog`）：正文 `el-input textarea` → Milkdown 编辑器组件；标题/类型选择不变；「创建」时取 `editor.getMarkdown()` 作为 `rawText` 提交（`knowledge.createNote` 契约不变）
2. **详情页编辑**（`KnowledgeDetailPage.vue`）：
   - 进入编辑：用 `document.rawText` 初始化编辑器（`editor.setMarkdown`）
   - 保存：`editor.getMarkdown()` → `knowledge.update({ id, rawText })`（主进程重新分块逻辑**不动**）；成功 toast「已保存并重新分块」沿用
   - 取消编辑：丢弃改动（不写库）
3. **查看态**：保持现有 `<pre>` 纯文本（改动最小）**或**换用已有 `MarkdownView.vue`（Vditor 只读渲染，让 markdown 文档查看更友好）——二选一，**优先复用 MarkdownView**（成本低、已有组件）；若换，注意 `rawText` 为空/纯文本时正常显示
4. **样式**：Milkdown 编辑器样式与页面浅色主题协调（默认主题可接受，如与项目视觉冲突则做最小化 CSS 覆盖，作用域限定在编辑器容器内，不影响页面其它区域）
5. **编辑器生命周期**：弹窗打开/关闭、编辑态切换时正确创建/销毁编辑器实例，避免重复挂载；`v-if` 控制挂载时机
