## 二、任务总览（五大块）

1. **数据模型升级**：迁移 006 新增 `knowledge_base`、`knowledge_folder` 两表；`document` 加 `kb_id`、`folder_id` 可空外键；存量文档归入自动创建的「默认知识库」
2. **服务端**：知识库 CRUD、文件夹树 CRUD（多级、循环检测）、文档归属（列表筛选按库/文件夹、移动文档同步归属）、标签管理（CRUD + 重命名全局生效 + 按标签浏览）
3. **Milvus v2**：`knowledge_chunk_v2` collection（字段加 kb_id/folder_id），search 支持 filter 表达式；存量向量 v1→v2 迁移（补归属、不重嵌入、行数校验）
4. **设置页**：知识库存储区块（collection 名称可配置、健康状态、迁移提示）
5. **UI 重构**：知识库页改为「左侧知识库列表 + 文件夹树 / 右侧文档列表 + 面包屑」；新建文档（Milkdown）与导入入口支持选库；文档移动入口；新增标签管理页

**核心思想**：库 = 检索过滤边界（一个库一个话题域），文件夹 = 库内组织，标签 = 跨库横向关联；Milvus 保持单 collection + 标量字段过滤，不拆库。

## 五、实现要求

### 5.1 迁移 006（D-1）

`migrations/006_knowledge_base.sql`（新增）：

- `knowledge_base`：`id CHAR(36) PK`、`name VARCHAR(50) NOT NULL`、`description TEXT NULL`、`color VARCHAR(16) NULL`（可选图标色，UI 展示用）、`sort INT NOT NULL DEFAULT 0`、`created_at/updated_at DATETIME(3) NOT NULL`；`UNIQUE KEY uk_kb_name (name)`
- `knowledge_folder`：`id CHAR(36) PK`、`kb_id CHAR(36) NOT NULL`、`parent_id CHAR(36) NULL`（NULL=库根，自引用）、`name VARCHAR(50) NOT NULL`、`sort INT NOT NULL DEFAULT 0`、`created_at/updated_at DATETIME(3) NOT NULL`；FK→knowledge_base，自引用 FK ON DELETE CASCADE（仅允许级联清理子文件夹的孤儿场景由服务端规则控制，见 §5.2）；`UNIQUE KEY uk_folder_kb_parent_name (kb_id, parent_id, name)`
- `document` 加列：`kb_id CHAR(36) NULL`、`folder_id CHAR(36) NULL`；FK→knowledge_base（SET NULL）/knowledge_folder（SET NULL）
- **存量初始化（幂等）**：`INSERT INTO knowledge_base` 一条「默认知识库」（固定 id 用 `'default'` 字符串或稳定 UUID，**不重复插入**）；`UPDATE document SET kb_id='默认库id' WHERE kb_id IS NULL`（含软删除文档，保持可恢复视图完整）

### 5.2 知识库与文件夹服务（D-2）

`src/main/modules/knowledge/` 新增 `kb.ts`（或并入现有 service，命名与现有风格一致）：

- **知识库**：create（名称必填、≤50 字、重名校验）、update（名称/说明/颜色/排序）、remove（**有文档 → 抛 `INVALID_STATE`「库内有文档，请先移动或删除」**；否则连文件夹一起删）、list（按 sort/created_at 排序，返回各库文档计数与文件夹计数）
- **文件夹**：create（name 必填、≤50 字、kb_id 必填、parent_id 可选）、update（改名）、remove（**有子文件夹或文档 → 抛 `INVALID_STATE`「文件夹非空，不能删除」**）、list（按 kb_id 返回树形：id/parentId/name/sort/children）
- **循环检测**：create/update 时 parent_id 不能等于自身；update 时不能指向自己的后代（BFS 校验，抛 `INVALID_STATE`）
- **删除库/文件夹均不提供级联静默删除**（K5）
- 文件夹层级**不设深度上限**（语雀式多级），但 UI 展示最多展开 3 级样式适配

### 5.3 文档归属与移动（D-3）

- `knowledgeListSchema`（contracts/knowledge.ts）**扩展**：`kbId`（可选 UUID）、`folderId`（可选 UUID）；`folderId` 与 `kbId` 同时传入时以 folderId 归属校验一致（folder 必须属于该 kb，不一致抛 `INVALID_STATE`）；现有 `docType/tag/keyword/includeDeleted` 语义不变
- 文档创建入口（导入/剪藏/手写/升格）**新增归属参数**：`kbId`（默认上次选择的库，无则默认库）、`folderId` 可选；K02-F10 管线入库时写入 document.kb_id/folder_id
- **移动文档**：新接口 `knowledge.moveDocument({ id, kbId, folderId })`：
  - 校验目标库/文件夹存在；folderId 非空时其 kb_id 必须等于目标 kbId
  - 单事务更新 MySQL document.kb_id/folder_id
  - **同步 Milvus**：该文档全部 chunk 的 kb_id/folder_id 更新（delete by document_id + 带新归属 upsert，或 SDK 支持 update 则用 update；以实际 SDK 能力为准，**不得只改 MySQL**）
  - 返回新归属；失败可重试（幂等：重复移动同目标不报错）
- **删除文档**：软删除（deleted_at）不变；Milvus chunk 清理沿用现有逻辑，不因本任务改变

### 5.4 Milvus v2 与迁移（D-4）

`src/main/infrastructure/milvus/`：

- **collection v2**：`MILVUS_COLLECTION = "knowledge_chunk_v2"`（名称常量，构造可覆盖，见 §5.5 设置）；字段：`chunk_id`(PK, VarChar 36) / `document_id`(VarChar 36) / **`kb_id`(VarChar 36)** / **`folder_id`(VarChar 36)** / `model_version`(VarChar 128) / `embedding`(FloatVector, dim 来自 embedding provider)；索引 HNSW COSINE 沿用；`enable_dynamic_field:false`
- **search 支持 filter**：`search(vector, topK, filter?)`，filter 为 Milvus 标准表达式字符串（如 `kb_id == "xxx"`、`kb_id in ["a","b"]`）；构造 client.search 时传 `expr`；filter 为空时不传
- **ensureCollection**：按 v2 字段创建；维度不一致仍只警告不重建（沿用现有策略）
- **v1→v2 存量迁移**：`migrateV1toV2()`：
  1. `exportAll(v1)` 取全部存量 chunk（chunkId/documentId/modelVersion/embedding）
  2. 按 documentId 批量查 MySQL `document` 拿 kb_id/folder_id（join 或 IN 查询；**查不到的文档 → 归默认库**）
  3. `importAll(v2)` 写入（含归属字段）
  4. `count(v2)` 与导出行数**必须一致**，否则抛错中止、不切换默认 collection
  5. 成功后默认 collection 指向 v2（后续读写均用 v2）
  - 迁移入口：设置页按钮触发 + 首次启动检测（v2 不存在且 v1 有数据 → 提示用户执行，**不自动执行**，避免启动卡顿）
- **备份/恢复适配**：`backup/service.ts` 向量导出改读 v2；恢复按 v2 字段重建后 importAll（含归属）

### 5.5 标签管理与设置项（D-5）

- **标签管理服务**（复用现有 tag/entity_tag 表）：`tag.list`（全部标签 + 各标签文档数）、`tag.rename`（**UPDATE tag.name，所有实体自动跟随**；新名重复 → 合并为该标签并删除旧标签）、`tag.remove`（仅解绑，不删文档）；文档打标/去标沿用现有逻辑
- **设置项** `knowledge.storage`（app_setting 受控键，schema 与白名单同步 `system.ts`）：`{ collectionName: "knowledge_chunk_v2" }`（必填、合法 Milvus 命名校验）；页面可改 + 「执行存量迁移」按钮（调用 §5.4 migrate）+ 健康状态（collection 是否存在/维度/行数，复用现有 milvus health）

### 5.6 UI（D-6）

`src/renderer/features/knowledge/`：

- **知识库页重构**（对齐交互演示）：
  - 左侧栏：顶部「知识库」列表（名称 + 文档数，可选中、新建、编辑、删除）+ 下方「文件夹」树（当前库的文件夹，多级缩进，可展开/新建/改名/删除）

  - 文档行操作：打开详情（Milkdown 编辑沿用）、移动（弹出库+文件夹选择器）、导出、删除——移动入口是本任务新增

## 八、技术决策（已锁定，直接执行）

| 项 | 决策 |
|---|---|
| Milvus 组织 | 单 collection + kb_id/folder_id 标量字段过滤（K1）；不拆库、不用 partition |
| collection | `knowledge_chunk_v2`（设置页可配，默认此名）；v1 保留不删（可回退） |
| 存量迁移 | exportAll(v1) → join document 补归属（缺失归默认库）→ importAll(v2) → count 一致才切换（K3） |
| 默认库 | 迁移自动建「默认知识库」，存量归入；新建文档默认上次选择库 |
| 删除规则 | 非空库/非空文件夹禁止删除（K5）；文件夹 parent_id 循环拦截 |
| 移动同步 | MySQL 事务更新 + Milvus delete+upsert 同步 kb_id/folder_id（K6） |
| 标签 | tag 表 CRUD + 重命名全局生效 + 删除仅解绑（K7） |
| 文件夹 | parent_id 树形、多级、不跨库（K4） |
| chunk 表 | 不加列；Milvus chunk 冗余 kb_id/folder_id（查询过滤用） |
| UI | 左侧库+文件夹树 / 右侧文档列表 + 面包屑；移动用菜单/按钮（拖拽 P2） |
