## 五、实现要求

### 5.1 LLM Provider（`src/main/infrastructure/llm/`）

目录内文件建议：`types.ts`（接口+配置类型）、`openai-compatible.ts`（实现）、`index.ts`（工厂），删除原有空壳 TODO。

```ts
// types.ts —— 接口定义
export interface ChatMessage { role: "system" | "user" | "assistant"; content: string; }
export interface ChatRequest {
  messages: ChatMessage[];
  model: string;
  temperature?: number;          // 默认 0.7
  maxTokens?: number;            // 默认 2048
  stream?: boolean;              // 本期仅支持 false（非流式），true 留 TODO(P1-5)
}
export interface ChatResult { content: string; usage?: { promptTokens: number; completionTokens: number }; model: string; }

export interface LlmProvider {
  chat(req: ChatRequest): Promise<ChatResult>;
  healthCheck(): Promise<{ ok: boolean; detail: string }>;   // 最小请求：发 1 条 "ping" 消息
}
```

`openai-compatible.ts` 实现要点：
- 构造函数接收 `{ baseURL, apiKey, model }`；`baseURL` 末尾无 `/`，请求拼 `baseURL + "/v1/chat/completions"`
- 请求体：`{ model, messages, temperature, max_tokens }`；`Authorization: Bearer ${apiKey}`（Ollama 本机可留空，见 5.2 说明）；`Content-Type: application/json`
- **超时**：单次请求 30s（`AbortController`）；失败**重试 3 次**，指数退避 1s/2s/4s，仅对网络错误/5xx 重试，4xx 不重试（鉴权失败立刻返回）
- 错误分类映射：HTTP 401/403 → `AI_AUTH_ERROR`；网络错误/超时/5xx → `AI_UNAVAILABLE`；不要向渲染层泄露响应原文细节，`message` 给出可读原因
- 不缓存、不持久化任何请求内容

### 5.2 Embedding Provider（`src/main/infrastructure/embedding/`）

```ts
export interface EmbeddingProvider {
  embed(texts: string[]): Promise<{ vectors: number[][]; model: string; dim: number }>;
  healthCheck(): Promise<{ ok: boolean; detail: string; dim?: number }>;  // 测试时请求单条文本返回维度
}
```

实现要点（Ollama OpenAI 兼容端点，`http://127.0.0.1:11434/v1/embeddings`）：
- 配置 `{ baseURL, model }`，无 apiKey（Ollama 本机免鉴权；header 留空即可，**不要**因为没 key 报错）
- 请求体：`{ model, input: texts }`（OpenAI 兼容：input 可为字符串或数组；本实现传数组）
- 响应解析：`data[]` 每项 `.embedding: number[]`，顺序与输入一一对应；`dim = vectors[0].length`
- **维度记录**：`healthCheck` / `embed` 都返回 `dim`（供后续 Milvus collection 维度配置化使用，P1-2 消费）
- 超时 30s、重试策略同 5.1
- 空数组输入直接抛 `VALIDATION_ERROR`（防无效请求）

export const llmSettingsSchema = z.object({

### 5.4 Settings 服务扩展（`src/main/modules/settings/service.ts`）

- 存储：沿用 P0 的 `app_setting` 表 + safeStorage 模式，受控键：
  - `llm.chat`：`value_json = { provider, baseURL, model, apiKeyEncrypted }`（apiKey = `safeStorage.encryptString(apiKey)` 的 base64）
  - `llm.embedding`：`value_json = { baseURL, model }`（无密钥）
- 方法：
  - `saveLlmConfig(input)` / `saveEmbeddingConfig(input)`：Zod 校验 → 加密存储 → 返回健康状态（存后立即测试一次）
  - `getAiConfigs()`：返回**脱敏**配置——apiKey 只显示掩码（保留前 4 后 4，中间 `****`，长度 ≤8 全掩码）；**绝不允许**把明文密钥发给渲染层
  - `testLlmConnection(input)`：用传入配置（明文）构造 provider → `healthCheck` → 返回 `llmTestResultSchema` 结构；测试用配置**不落盘**（区别于保存）
  - `testEmbeddingConnection(input)`：同上，返回维度
  - `getAiHealth()`：读取已存配置 → 两个 provider 各跑一次健康检查 → 返回 `aiHealthSchema` 结构；未配置时 `ok:false, detail:"未配置"`，**不报错、不崩溃**
- 所有 AI 方法失败时抛 `AI_UNAVAILABLE` / `AI_AUTH_ERROR` 结构化错误（复用 P0 `failure()` 包装）；AI 服务异常**绝不**影响其他设置读写

| 端点 | 请求 | 响应关键字段 |
|---|---|---|
| `POST {baseURL}/v1/chat/completions` | `{model, messages:[{role,content}], temperature, max_tokens}` | `choices[0].message.content`、`usage.prompt_tokens/completion_tokens` |
