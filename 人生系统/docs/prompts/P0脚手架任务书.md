## 五、交付物与实现要求

### 5.1 工程骨架与安全基线（架构文档 2.2、3.1、7）

- 技术栈：Electron + Vue 3（组合式 API）+ TypeScript + Vite + Pinia + Vue Router + **Element Plus** + **Drizzle ORM + mysql2**（架构文档推荐，直接采用，不再讨论）
- 打包：electron-builder 配 Windows 目标即可，**不要求产出安装包**
- 安全基线四项**必须全部落实**：`contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`、CSP 禁止未知外部脚本
- **进程边界**（架构适应度函数，用 ESLint import 规则或 CI 脚本强制）：
  - 渲染层（`src/renderer`）不得导入 `mysql2`、Milvus SDK、`fs`、`electron` 主进程 API
  - `src/shared/domain` 不依赖 Vue/Electron
  - 主进程不承载 UI 状态；不执行来自渲染层的任意路径/SQL
- 所有 IPC 走 `ipcMain.handle` 白名单 + Zod 参数校验 + 结构化返回值；Preload 用 `contextBridge.exposeInMainWorld` 暴露**按领域分组、参数受校验的窄 API**，绝不暴露裸 `ipcRenderer`/`send`
- 文件选择只走主进程原生对话框

### 5.2 MySQL 迁移（架构文档 4.1、4.2，附录 A 已全文照抄）

- 手写 SQL 迁移文件（**不要依赖 drizzle-kit 自动生成**，避免丢失 CHECK 约束、FULLTEXT、外键补挂顺序），迁移文件放 `life-system/migrations/`
- 自写简易迁移 runner：读 `schema_migrations` 表按序执行 + 记录已应用版本；支持**空库全量**与**增量升级**两种路径；失败回滚不半途
- 存储约定：InnoDB、`utf8mb4`、READ COMMITTED、连接池；`id` 与外键列 `CHAR(36)`（UUID）、时间 `DATETIME(3)` UTC、布尔 `TINYINT(1)`
- 全部 CHECK 约束值集与 FSD「枚举汇总表」完全一致（附录 D 已列出）；`document` 加 `FULLTEXT(title, raw_text) WITH PARSER ngram`（ngram_token_size=2，MySQL 8 默认）
- 外键创建顺序处理：`inbox_item.document_id`、`document.promoted_from_timeline_id` 在迁移末尾补挂；`entity_link` 是多态关联，无外键约束，应用层校验
- 迁移入口：主进程启动时「检测迁移版本 → 未迁移则自动执行」（可先弹设置页要求填连接串再做），并提供一个 `npm run db:migrate` 独立命令便于手动执行

### 5.3 主进程模块（架构文档 7 目录照抄，附录 B）

- `bootstrap/`：生命周期、窗口创建、安全策略、CSP
- `ipc/`：按上下文注册 typed handlers（goals/projects/tasks/habits/dashboard/search/settings/backup），每个 channel 有 Zod schema
- `modules/`：goals、knowledge（空壳）、wellbeing（空壳）、delivery（空壳）、search、backup
- `infrastructure/`：`db/`（连接池、迁移 runner、事务工具）、`migrations/`、`filesystem/`（应用数据目录：`userData` 下建 `data/`、`backups/`）、`export/`、`parser/`（空壳）、`embedding/`（空壳）、`llm/`（空壳）
- `workers/`：空目录 + README 说明 P1 使用
- 连接管理：MySQL 连接信息从设置读取（存 `app_setting`，密码字段用 Electron `safeStorage` 加密后存）；提供 `testConnection()`（MySQL 实测 SELECT 1）、健康检查（服务可达性状态）；**Milvus 在 P0 只保存连接配置 + 测试按钮置「未启用（P1）」降级态**
- 连接不可达时：所有 DB 操作返回结构化错误 `DB_UNAVAILABLE`，界面显示原因并引导到设置页，应用不崩溃

### 5.4 Preload API（架构文档 2.2 / 7）

- `contextBridge.exposeInMainWorld('lifeSystem', {...})`，按领域分组：`goals.*`、`projects.*`、`tasks.*`、`habits.*`、`dashboard.*`、`search.*`、`settings.*`、`backup.*`
- 每个方法签名与主进程 handler 一一对应，参数在 preload 侧也做一次校验；DTO 类型定义在 `src/shared/contracts/`

### 5.5 渲染层（架构文档 7）

- `src/renderer/app/`：路由（Dashboard/目标/项目/待办/习惯/设置 + 详情页）、布局（侧栏导航 + 主区）、Pinia 根配置与调用状态封装
- `src/renderer/features/`：dashboard / goals / tasks / habits / settings 五个 feature；knowledge、timeline、wellbeing、delivery 只留目录 + TODO
- `src/renderer/shared/`：UI 复用（Element Plus 二次封装）、格式化工具（日期本地时区转换、进度百分比）、API client
- **页面只通过 preload API 取数据**，Pinia 仅保存 UI 会话状态与加载/错误/空状态，业务事实源是 MySQL
- 视觉：Element Plus 默认主题即可；布局参考原型 P0 相关页的「每页一个主操作」原则与信息密度，**不做精细视觉设计**（那是后续设计任务）
- 每页落实 loading / error / empty 三态；错误按错误码分类提示（`DB_UNAVAILABLE` → 引导设置页）

### 5.6 P0 业务规则落实要点（FSD 详述为准，此处仅强调高频易错项）

- **目标进度只在查询层计算，绝不写回 goal 表**；任务数/打卡数不得换算目标进度
- progress 计算：numeric = `(最新recorded_at的value - start_value) / (target_value - start_value)`，夹 0~100%；milestone = `is_done=1 数量/总数`；status 无百分比
- 时间：数据库存 UTC，展示转本地；`same day 多次录数据点取最新值`；习惯 `checked_on` 按用户本地日
- 状态机严格按 FSD（如待办 todo→doing→done 后不可再推进、可显式撤销回 todo；done 目标只读；项目 done 后不可回 active 等）
- 删除：除 document 外均为**二次确认后硬删除并级联**；task/project 被删除时对方外键置空不级联删
- 习惯标 `frequency_type` 与 `weekly_target` 互斥 CHECK；打卡同 habit+date 唯一、幂等；streak 算法按 FSD 详述
- 全文搜索：MySQL FULLTEXT(natural language mode) 检索 `title`+`raw_text`（P0 阶段 document 表无数据，先对目标/项目/待办/习惯按标题做 LIKE/索引检索与标签过滤，**搜索能力骨架打通**），标签过滤走 `tag`/`entity_tag` join，类型/状态过滤走普通索引

### 5.7 备份 / 恢复 / 导出（架构文档 6，FSD S01-F06~F09）

- 备份：主进程调用受控 `mysqldump --single-transaction` 导出逻辑库；生成 manifest（schema 版本、应用版本、备份时间、SHA-256）；备份目录 `userData/backups/<timestamp>/`；**失败不覆盖旧备份**
- 恢复：先 dump 当前库作为安全点 → 校验所选备份 manifest 与 SHA-256 → 导入空库 → 表计数校验；失败回滚到安全点
- 导出 JSON：目标/项目/待办/习惯的版本化 DTO（含记录数与 hash 校验）
- 导出 Markdown/TXT：各实体规范化文本（标题、字段、状态、时间），可读性优先
- 所有备份/导出任务在主进程执行，进度经 IPC 推送，UI 在「系统任务状态」页展示（S01-F10）

### 5.8 站内提醒（H01-F03 / S01-F04·F05）

- P0 实现为**查询时计算**的站内聚合（不做系统通知）：目标 3 天内到期 / 今日未打卡习惯 / 待录入数据点目标；开关与频率存 `app_setting`，设置页可配
- 降噪选项默认值按 FSD/设计文档（主动推荐默认关闭——P2 功能，仅把开关字段与存储备好）

## 六、硬约束（违反即返工）

1. 渲染层禁入 mysql2/Milvus SDK/**fs**/electron 主进程 API；所有数据访问经 preload
2. 所有 IPC channel 必须有 Zod schema；禁止 `ipcRenderer.send` 裸通道
3. 字段与 schema 一一对应，**不发明新字段**；确需新增 → 记入 `docs/decisions/` 待定
4. 枚举值集必须与 FSD 枚举汇总表（附录 D）完全一致，写进 CHECK 约束
5. 情绪数据不进 RAG/搜索（P0 无情绪功能，但 wellbeing 模块空壳不得被任何 P0 页面 import）
6. 目标进度不得由行动数量驱动；任务/习惯不改变目标进度
7. 迁移必须可从空库一键执行，且可增量升级；schema 与架构文档 4.2 逐表核对
8. 时间存 UTC `DATETIME(3)`；ID 为 UUID `CHAR(36)`；编码 `utf8mb4`
9. 中文界面与注释；不引入任何商业/交付黑话（如 MVP 只作发布门描述用，界面文案不出现）
10. **行级注释**：核心业务方法、状态流转分支、校验规则、进度计算、streak 算法等必须逐行或逐逻辑块加中文注释，说明「做了什么 + 为什么这么做」，禁止只有代码没有注释；迁移 SQL 的每张表、每个 CHECK 约束、FULLTEXT 与补挂外键处都要有行级注释解释用途
11. **禁止压缩代码**：源码、迁移脚本、配置文件一律保持未压缩、可读格式；变量名/函数名不缩写不混淆；vite 构建配置关闭 minify（`build.minify: false` 或等效），不使用 terser/uglify 等压缩插件，确保任何人拿到工程能直接读懂每一行

## 附录 A：MySQL Schema（架构文档 4.2 全文照抄，迁移必须与此一致）

```sql
CREATE TABLE schema_migrations (id TEXT PRIMARY KEY, applied_at TEXT NOT NULL);

CREATE TABLE goal (
  id TEXT PRIMARY KEY, title TEXT NOT NULL, description TEXT,
  period TEXT NOT NULL CHECK(period IN ('annual','quarterly','monthly')),
  metric_type TEXT NOT NULL CHECK(metric_type IN ('numeric','milestone','status')),
  unit TEXT, start_value REAL, target_value REAL,
  status TEXT NOT NULL DEFAULT 'active' CHECK(status IN ('active','done','abandoned')),
  due_date TEXT, created_at TEXT NOT NULL, updated_at TEXT NOT NULL,
  CHECK((metric_type = 'numeric' AND start_value IS NOT NULL AND target_value IS NOT NULL AND target_value <> start_value)
     OR (metric_type <> 'numeric' AND start_value IS NULL AND target_value IS NULL))
);
CREATE TABLE goal_record (
  id TEXT PRIMARY KEY, goal_id TEXT NOT NULL REFERENCES goal(id) ON DELETE CASCADE,
  value REAL NOT NULL, note TEXT, recorded_at TEXT NOT NULL, created_at TEXT NOT NULL
);
CREATE TABLE milestone (
  id TEXT PRIMARY KEY, goal_id TEXT NOT NULL REFERENCES goal(id) ON DELETE CASCADE,
  title TEXT NOT NULL, is_done INTEGER NOT NULL DEFAULT 0 CHECK(is_done IN (0,1)),
  done_at TEXT, sort_order INTEGER NOT NULL DEFAULT 0, created_at TEXT NOT NULL, updated_at TEXT NOT NULL
);
CREATE TABLE project (
  id TEXT PRIMARY KEY, goal_id TEXT REFERENCES goal(id) ON DELETE SET NULL,
  title TEXT NOT NULL, description TEXT,
  status TEXT NOT NULL DEFAULT 'active' CHECK(status IN ('active','done','paused')),
  start_at TEXT, end_at TEXT, created_at TEXT NOT NULL, updated_at TEXT NOT NULL
);
CREATE TABLE task (
  id TEXT PRIMARY KEY, goal_id TEXT REFERENCES goal(id) ON DELETE SET NULL,
  project_id TEXT REFERENCES project(id) ON DELETE SET NULL,
  title TEXT NOT NULL, note TEXT, due_date TEXT,
  status TEXT NOT NULL DEFAULT 'todo' CHECK(status IN ('todo','doing','done')),
  completed_at TEXT, created_at TEXT NOT NULL, updated_at TEXT NOT NULL
);
CREATE TABLE habit (
  id TEXT PRIMARY KEY, name TEXT NOT NULL, note TEXT,
  frequency_type TEXT NOT NULL CHECK(frequency_type IN ('daily','weekly_times')),
  weekly_target INTEGER CHECK(weekly_target BETWEEN 1 AND 7),
  streak INTEGER NOT NULL DEFAULT 0, last_done_on TEXT, created_at TEXT NOT NULL, updated_at TEXT NOT NULL,
  CHECK((frequency_type='daily' AND weekly_target IS NULL) OR (frequency_type='weekly_times' AND weekly_target IS NOT NULL))
);
CREATE TABLE habit_checkin (
```

## 附录 C：P0 关键规则速查（完整规则以 FSD 详述为准）

- 安全：`contextIsolation:true` / `sandbox:true` / `nodeIntegration:false` / CSP；IPC 全部 `handle`+Zod；Preload 窄 API
- 存储：InnoDB / utf8mb4 / READ COMMITTED / 连接池；UUID CHAR(36)；时间 DATETIME(3) UTC，展示转本地
- 进度：查询层计算不写回；numeric 取最新记录，milestone 比率，status 无百分比
- 状态机：目标 active→done|abandoned（结束后只读）；项目 active↔paused→done（done 不回 active）；待办 todo→doing→done（done 可撤销回 todo）；习惯打卡唯一幂等
- 删除：除 document 外二次确认硬删除；task/project 被删对方外键置空
- 搜索：FULLTEXT ngram 中文；标签走 entity_tag；类型/状态走普通索引
- 备份：mysqldump --single-transaction + manifest(SHA-256)；恢复先存安全点；失败不覆盖旧备份
- 断连：`DB_UNAVAILABLE` 错误码，界面引导设置页，不崩溃
- 可读性：业务代码/迁移 SQL 行级中文注释；构建关闭 minify，不压缩不混淆
