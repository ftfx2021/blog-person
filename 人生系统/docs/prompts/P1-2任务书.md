### 5.1 Milvus 基础设施（`src/main/infrastructure/milvus/`）

#### 5.1.1 类型（`types.ts`）

```ts
// chunk 向量记录：chunk_id 必须能回查 MySQL chunk.id，严禁写入情绪数据。
export interface MilvusChunkRecord {
  chunkId: string;        // MySQL chunk.id（UUID CHAR(36)）
  documentId: string;     // MySQL document.id
  modelVersion: string;   // 生成向量的 embedding 模型名（如 "qwen3-embedding:0.6b"）
  embedding: number[];
}
// 健康检查结果：detail 只给可读原因，不泄露服务端原始堆栈。
export interface MilvusHealthResult {
  ok: boolean;
  detail: string;
  version?: string;                 // Milvus 服务端版本（获取失败可省略）
  latencyMs?: number;               // 连接 + 检查耗时
  collection?: {
    exists: boolean;
    dim?: number;                   // 已存在 collection 的向量维度
    rowCount?: number;              // 当前向量数
    expectedDim?: number;           // 当前 embedding 模型维度（用于不一致提示）
  } | null;
}
// chunk 存取端口：备份/恢复/后续 RAG 共用，主进程内唯一 Milvus 访问面。
export interface MilvusRepository {
  ensureCollection(dim: number): Promise<{ created: boolean; dim: number }>;
  upsertChunks(records: MilvusChunkRecord[]): Promise<void>;
  queryByDocumentId(documentId: string): Promise<MilvusChunkRecord[]>;
  search(vector: number[], topK: number): Promise<Array<{ chunkId: string; score: number }>>;
  count(): Promise<number>;
  deleteByDocumentId(documentId: string): Promise<void>;
  exportAll(): Promise<MilvusChunkRecord[]>;          // 备份：全量导出
  importAll(records: MilvusChunkRecord[]): Promise<void>;  // 恢复：批量 upsert
  dropAndRecreate(dim: number): Promise<void>;        // 恢复：整体重建
  health(): Promise<MilvusHealthResult>;
}
```

#### 5.1.2 连接管理（`client.ts`）

- 构造函数接收 `MilvusSettings`（见 §5.2 schema），创建 `new MilvusClient({ address, username, password, ssl, timeout: connectTimeout, maxRetries: 3 })`，`await client.connectPromise` 确认连接
- 单例 + 引用计数：`getClient(settings)` 首次创建、后续复用；`close()` 时 `client.closeConnection()`；设置保存/健康检查/备份各自生命周期由调用方管理，**不跨调用持有长连接**（备份与设置互不干扰）
- 连接失败/鉴权失败统一抛 `VECTOR_DB_UNAVAILABLE` 结构化错误（复用 P0 `failure()` 包装或 `Object.assign(new Error(), { code })`，与现有 `DB_UNAVAILABLE` 抛出方式一致），message 给可读原因（如「无法连接 Milvus：请检查地址与端口」「鉴权失败：请检查用户名/密码」），**不**向渲染层泄露服务端响应原文

#### 5.1.3 Collection 生命周期（`collection.ts`）

`knowledge_chunk_v1` schema（固定，维度由调用方传入）：

```ts
fields = [
  { name: "chunk_id",      data_type: DataType.VarChar,  max_length: 36,  is_primary_key: true },
  { name: "document_id",   data_type: DataType.VarChar,  max_length: 36,  is_primary_key: false },
  { name: "model_version", data_type: DataType.VarChar,  max_length: 128, is_primary_key: false },
  { name: "embedding",     data_type: DataType.FloatVector, dim },   // dim 来自 embedding 模型，配置化
];
index_params = [
  { field_name: "embedding", index_type: "HNSW", metric_type: MetricType.COSINE,
    params: { M: 16, efConstruction: 200 } },
];
enable_dynamic_field: false;   // 禁止动态字段，防止脏键进入向量库
```

`ensureCollection(dim)`：
1. `describeCollection({ collection_name: "knowledge_chunk_v1" })` → 不存在 → `createCollection({ collection_name, fields, index_params, enable_dynamic_field: false })` → `loadCollection({ collection_name })`，返回 `{ created: true, dim }`
2. 已存在 → 读取其 embedding 字段维度 → 与传入 `dim` 比较：一致返回 `{ created: false, dim }`；**不一致不自动重建**，返回 `{ created: false, dim: 实际维度 }` 且 health 中携带 `expectedDim`，由上层提示「embedding 模型维度与 collection 不匹配」
- `createCollection` 若因 SDK 版本不支持内联 `index_params`，改用 `createIndex({ collection_name, field_name: "embedding", index_type: "HNSW", metric_type: "COSINE", params: { M: 16, efConstruction: 200 } })` 单独创建——两种方式二选一，**验收以"索引存在且可 search"为准**
- `dropAndRecreate(dim)`：`releaseCollection`（若已加载）→ `dropCollection` → 重新走 createCollection + loadCollection

#### 5.1.4 Chunk 存取（`repository.ts`）

- `upsertChunks`：按每批 ≤ 500 条 `client.upsert({ collection_name, data })`，字段名一一映射（`chunk_id`/`document_id`/`model_version`/`embedding`）；任一 upsert 失败抛 `VECTOR_DB_UNAVAILABLE`
- `queryByDocumentId`：`client.query({ collection_name, filter: 'document_id == "xxx"', output_fields: ["chunk_id","document_id","model_version","embedding"], limit: 16384 })` → 映射为 `MilvusChunkRecord[]`
- `search`：`client.search({ collection_name, data: [vector], anns_field: "embedding", limit: topK, output_fields: ["chunk_id"], search_params: { metric_type: "COSINE", params: { ef: 64 } } })` → 返回 `{ chunkId, score }` 列表（score 从返回的 distance/scores 取）
- `count`：`client.count({ collection_name })` → `Number(res.data)`
- `deleteByDocumentId`：`client.delete({ collection_name, filter: 'document_id == "xxx"' })`
- `exportAll`（备份用，全量导出）：**分页游标**读取，单页 `limit: 10000`（低于 Milvus 默认 max_limit 16384）：
  1. 第一页 `filter: 'chunk_id != ""'`（Milvus query 必须带 filter，用恒真式取全量），`output_fields` 全字段
  2. 后续页 `filter: 'chunk_id > "上一页最后一条 chunk_id"'`（主键字典序游标，避免 offset 全量扫描；chunk_id 为 UUID 字符串，字典序唯一且稳定）
  3. 返回空页即结束
  - 每条记录 `embedding` 是 `number[]`，直接入结果数组；数据量在数万 chunk 级别，内存可容纳
- `importAll`（恢复用）：按每批 ≤ 500 条 `upsert`，全部成功才算完成


流程（在既有 create 的 MySQL 步骤之后追加）：
1. **MySQL 步骤**（保留）：dump → SHA-256 → `tableCounts`。**注意**：`tableCounts` 的静态表清单从「P0 七表」扩展为「P0 七表 + P1 知识表」——`document`、`chunk`、`inbox_item`、`timeline_entry`、`mood_word`、`mood_record`、`mood_report`，保证备份校验覆盖知识数据（表名固定数组，不拼接外部输入）
2. **Milvus 步骤**：
   - 读取 `milvus.connection`（`settingsService` 暴露只读方法或直接读 `app_setting`）：
     - **未配置** → `manifest.milvus = null`，跳过向量备份（与 v1 语义一致，备份仍成功）
     - **已配置** → 连接 → `ensureCollection(dim)`（dim 取当前 embedding 模型维度，embedding 未配置时用 collection 实际维度）→ `exportAll()` → 写 `milvus-vectors.json`（**紧凑 JSON，不缩进**）→ `count()` 校验导出条数 → 计算向量文件 SHA-256 → 填 `manifest.milvus`
     - **已配置但连接/导出失败** → 整体备份失败（**不产生不完整备份**，符合 S01-F06 规则⑤），既有 `BACKUP_FAILED` 兜底清理临时目录、保留旧备份
3. **原件副本步骤**：源目录 `paths.documents`（见 §5.6.3）若存在且非空 → 递归复制到临时目录下 `originals/`，保持相对路径；逐文件记录 `{ name, size, sha256 }`；不存在则 `originals = { fileCount: 0, files: [] }`。**绝不**复制 `data/mysql-connection.json` 等配置文件
4. 写 manifest v2 → 原子 `rename` 发布（沿用既有提交点）

#### 5.6.2 恢复（`restore` 扩展）

在既有 restore 的「校验 manifest → 建立安全点 → 恢复 MySQL → 表计数校验」基础上扩展：

1. **manifest 版本兼容**：读取 `formatVersion`——`1`（或无 `milvus` 字段）→ 按 v1 流程只恢复 MySQL，完成后返回结果并附带 `milvusSkipped: true, message: "该备份不含向量数据"`；`2` → 完整流程
2. **建立安全点**（在恢复前，与 MySQL 安全点并列）：
   - MySQL 安全点：既有 `createDump(safety)` 保留
   - **Milvus 安全点**：连接当前 Milvus → `exportAll()` → 写入 `restore-safety-milvus.json`（临时文件）；当前 Milvus 未配置/不可用时记录 `milvusSafety: null`（后续 Milvus 恢复失败时提示人工处理）
3. **恢复 MySQL**（既有流程保留：SHA-256 校验 → 导入 → 表计数比对）
4. **恢复 Milvus**（仅 `manifest.milvus` 存在时）：校验向量文件 SHA-256 与 `vectorCount` → `dropAndRecreate(dim)` → 读取向量文件 `importAll()`（分批 ≤500）→ `count()` 与 `manifest.milvus.vectorCount` 比对，不一致视为恢复失败
5. **一致性校验**：MySQL `chunk` 表 `COUNT(*)` 与 Milvus `count()` 比对——两者都必须等于 `manifest.tableCounts.chunk`（= `manifest.milvus.vectorCount`）；任一不一致 → 恢复失败
6. **失败回滚**：沿用既有 catch——先尝试 MySQL 回滚（安全点）；若 Milvus 步骤已执行且存在 Milvus 安全点，则 `dropAndRecreate(dim)` + `importAll(安全点数据)` 回滚 Milvus；回滚失败不删除安全点文件，错误信息附带路径供人工处理
7. 成功返回 `{ counts, safetyPoint, milvus: { restored: boolean, vectorCount?: number } }`

#### 5.6.3 目录

`src/main/infrastructure/filesystem/paths.ts` 的 `applicationPaths()` 返回对象**新增** `documents: join(root, "data", "documents")`（导入原件存放目录，P1-4 起使用；本期仅 mkdir 预留）。既有字段（data/backups/exports）不变，既有调用不受影响。

## 附录 A：Milvus SDK 速查（实现对照，2.5.x）

```ts
import { MilvusClient, DataType, MetricType } from "@zilliz/milvus2-sdk-node";

// 连接（address 为 "host:port"；等待连接就绪）
const client = new MilvusClient({ address: "127.0.0.1:19530", username: "", password: "", ssl: false, timeout: 10000, maxRetries: 3 });
await client.connectPromise;

// 健康检查与版本
const health = await client.checkHealth();          // { isHealthy: boolean; reasons: string[] }
const version = await client.getVersion();          // { version: string }（失败可忽略）

// 建 collection（2.5 支持内联 index_params；若类型报错改用 createIndex 单独调用）
await client.createCollection({
  collection_name: "knowledge_chunk_v1",
  fields: [
    { name: "chunk_id", data_type: DataType.VarChar, max_length: 36, is_primary_key: true },
    { name: "document_id", data_type: DataType.VarChar, max_length: 36 },
    { name: "model_version", data_type: DataType.VarChar, max_length: 128 },
    { name: "embedding", data_type: DataType.FloatVector, dim: 1024 },
  ],
  index_params: [
    { field_name: "embedding", index_type: "HNSW", metric_type: MetricType.COSINE, params: { M: 16, efConstruction: 200 } },
  ],
  enable_dynamic_field: false,
});
await client.loadCollection({ collection_name: "knowledge_chunk_v1" });   // search/query 前必须 load

// upsert / query / search / count / delete / drop
await client.upsert({ collection_name: "knowledge_chunk_v1", data: [{ chunk_id: "uuid", document_id: "uuid", model_version: "qwen3-embedding:0.6b", embedding: [0.1, 0.2, /* dim 个 */] }] });
const q = await client.query({ collection_name: "knowledge_chunk_v1", filter: 'document_id == "xxx"', output_fields: ["chunk_id","document_id","model_version","embedding"], limit: 16384 });
const s = await client.search({ collection_name: "knowledge_chunk_v1", data: [vector], anns_field: "embedding", limit: 20, output_fields: ["chunk_id"], search_params: { metric_type: "COSINE", params: { ef: 64 } } });
const n = await client.count({ collection_name: "knowledge_chunk_v1" });   // { data: number }
await client.delete({ collection_name: "knowledge_chunk_v1", filter: 'document_id == "xxx"' });
await client.dropCollection({ collection_name: "knowledge_chunk_v1" });
const list = await client.listCollections();        // { data: CollectionInfo[] }（名在 data[].name）

client.closeConnection();   // 结束连接
```

要点：
- `query` 的 `filter` 是**必填**；取全量用恒真式 `chunk_id != ""`
- 全量导出分页用主键字典序游标：`filter: 'chunk_id > "上一页末条 chunk_id"'`（避免 offset 全扫）
- 向量字段可通过 `output_fields` 回读，返回 `number[]`
- SDK 2.5.x 兼容 Milvus 2.5+ 服务端；用户本地部署版本未知时以 `npm ls @zilliz/milvus2-sdk-node` 版本为准

> - **输出**：成功显示记录数、向量数和一致性结果；失败提示回滚完成或人工处理项。
