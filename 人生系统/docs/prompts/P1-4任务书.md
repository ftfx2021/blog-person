### 5.3 解析器（P1-4-1 + P1-4-7）

`src/main/infrastructure/parser/` 下每个格式一个文件，`index.ts` 导出按 `doc_type` 分发的工厂。统一接口：

```ts
export interface ParseResult {
  rawText: string;                 // 规范化前的纯文本（可含 Markdown 标记）
  pageLocations?: { pageStart?: number; pageEnd?: number };  // 仅 PDF
  headingPath?: string[];          // 标题层级路径（PDF/DOCX/MD/HTML 尽力保留）
  charStart?: number;              // 解析源内的字符偏移（预留）
}
export interface DocumentParser {
  parse(storedPath: string): Promise<ParseResult>;
}
```

**逐格式约束（禁止项即返工点）**：

| 格式 | 实现要点 | **禁止** |
|---|---|---|
| PDF（`pdfjs-dist`） | 逐页 `getTextContent` 拼接，**记录页码边界**（页首/页尾 charStart/charEnd）；加密/损坏 → 抛错置 failed | 用 pdf-parse；只取第一页；扫描 PDF（无文本）假成功——必须检测到无文本时抛「需 OCR」错误 |
| DOCX（`mammoth`） | `convertToHtml` 或纯文本 + `extractRawText`；标题用 `convertToHtml` 的 heading 结构 → headingPath | 解压 zip 正则抽 `<w:t>` |
| Markdown（`unified`） | `remark-parse` 解析 AST，遍历 heading 记录标题层级；正文按 AST 重组（保序） | `split('\n')`；markdown-it 渲染后剥离标签 |
| HTML/网页（`cheerio`+`turndown`） | **先移除** `script/style/nav/header/footer/aside/form` 与 `aria-hidden` 节点 → `turndown` 转 Markdown；网页抓取：`fetch` + 超时（用设置值）+ 状态码校验 + Content-Type 校验；抓取失败**保留来源 URL**（抛可重试错误） | cheerio 全量 `text()`（导航/广告进正文）；不校验 URL/超时 |
| TXT（流式） | `fs.readFile` 按 Buffer 检测 BOM/编码（UTF-8、UTF-16LE/BE），解码后按段落分组 | 不处理 UTF-16；一次性读超大文件不设上限 |

- 解析**超时**：统一包裹 `Promise.race([parse, timeout])`，超时抛错置 failed（可重试），用设置值
- 全部解析器**禁止执行文档内脚本/宏/外部资源**；缺失定位字段用 null，**不得虚构**
- `parser/index.ts` 导出 `createParser(docType): DocumentParser`；doc_type 与扩展名映射：`.pdf→pdf`、`.docx→docx`、`.md/.markdown→markdown`、`.html/.htm→html`、`.txt→txt`

### 5.4 规范化（P1-4-2，K02-F12）

`src/main/modules/knowledge/normalize.ts`：
- 统一换行（CRLF→LF）、剔除控制字符与无意义空白，**保留**标题/列表/代码块/表格/引用/段落边界
- **不得**摘要/改写/补写原文
- 输出 `{ rawText, contentHash }`（`contentHash = sha256(rawText)`，复用既有 `hash` 工具）
- 规范化后为空 → 入库失败（抛错，保留输入）

### 5.5 分块（P1-4-3，K02-F13）

`src/main/modules/knowledge/chunk.ts`：

```ts
export interface ChunkOutput {
  seqNo: number;
  content: string;
  tokenCount: number;
  metadata: {
    documentTitle: string;
    docType: string;
    sourceUrl?: string | null;
    sourcePath?: string | null;
    headingPath?: string[];
    pageStart?: number | null;
    pageEnd?: number | null;
    charStart: number;
    charEnd: number;
  };
  contentHash: string;   // sha256(规范内容 + 稳定定位)
}
```

**算法（禁止固定长度 slice）**：
1. **先按标题和段落分组**：以标题（`#`~`######` / headingPath）为分节点，节内按空行分段落；PDF 按页码边界分节
2. 组内累计 token（`estimateTokens`）到 **400~700** 区间切块；相邻块**保留 80~120 token 重叠**（从前块尾部取重叠文本，重叠区按段落边界截取避免切词）
3. **代码/表格/引用不跨结构截断**：整块结构若超 700 token，允许单块超限并记录实际 token_count（不硬切）
4. `metadata`：`charStart/charEnd` 为原始 rawText 的字符偏移（切块时累计）；`headingPath` 取当前节路径；`pageStart/pageEnd` 仅 PDF 有值
5. `content_hash` 由规范内容 + 稳定定位计算，**重复执行相同输入必须产生相同逻辑分块**（幂等分块）
6. 同一文档 `seq_no` 从 0 连续；`raw_text` 非空但无法产生任何 chunk → 入库失败

### 5.6 统一入库管线（P1-4-4，K02-F10）

**`src/main/modules/knowledge/index.ts` 扩展**（保留既有 `ClipToDocumentInput` 接口与 `clipToDocument` 签名，替换占位实现）：

```ts
export interface IngestInput {
  title: string;
  docType: "webpage"|"pdf"|"docx"|"markdown"|"txt"|"html"|"note"|"skill"|"prompt"|"promoted";
  sourceUrl?: string;        // 网页/剪藏
  sourcePath?: string;       // 原文件路径（仅记录）
  storedPath?: string;       // 已复制到 data/documents 的原件
  rawText?: string;          // 手写/升格直接提供正文（跳过解析）
  content?: string;          // 收藏箱 snippet 剪藏传入（等价 rawText）
  tags?: string[];
  promotedFromTimelineId?: string;   // 升格时必填（P1-6 用）
}
export const knowledgeService = {
  clipToDocument: async (input: ClipToDocumentInput): Promise<{ documentId: string }>,  // 替换占位
  ingest: async (input: IngestInput): Promise<IngestResult>,                            // 完整管线入口
};
export interface IngestResult {
  documentId: string;
  chunkCount: number;
  parseStatus: "ready";
  indexStatus: "pending";
}
```

**编排顺序（固定，禁止跳步）**：
1. **采集校验**：doc_type/必填字段；文件导入先复制原件到 `data/documents/`（`applicationPaths().documents`），**复制失败不得开始入库**；URL 导入校验 http/https + 抓取
2. **元数据壳**：单事务写 `document`（`raw_text=''`、`parse_status=pending`、`index_status=pending`、来源/原件字段）+ `inbox_item` 回填（剪藏路径）；**幂等**：`sourceUrl/sourcePath` + 内容 hash 已存在 → 返回复用提示（不重复建）
3. **解析**（`rawText` 已提供则跳过，`storedPath` 存在则 `createParser(docType)` 解析）→ 失败更新壳为 `parse_status=failed` + 错误摘要（运行时字段），**保留原件与来源**
4. **规范化** → **分块** → 任一步失败：新建场景留 failed 壳，编辑场景保留旧版本
5. **MySQL 事务**：更新 document（title/raw_text/doc_type/parse_status=ready/index_status=pending/source/stored）+ **全量 chunk 插入**（新文档）；编辑场景**先删旧 chunk 再插新**（同一事务，避免新旧混合）
6. **触发 K03-F01 占位**：事务提交后调用 `indexingService.schedule(documentId)`（P1-5 实现；本期占位仅记录日志/保持 pending，**不写 Milvus**）
7. 失败回滚：事务回滚；新建保留 failed 壳，编辑保留旧正文/旧 chunk
8. **不得绕过**：任何调用方不得直接 import mysql 写 document/chunk

**收藏箱打通**：`clipToDocument` 占位替换为：link/read_later → 抓取网页 → `ingest({ docType: "webpage", ... })`；snippet → `ingest({ docType: "note", rawText: content })`。返回 `documentId`（原契约不变）。

## 附录 B：FSD K02 关键规则（原文内嵌，需求唯一依据）

> **K02-F01 导入文档**：单文件大小上限由设置读取；**先复制原件到受管目录，复制失败不得开始入库**；采集后调用 K02-F10 统一入库；支持语雀等平台手动导出后按文件导入，**不调用平台 API**；重复提交同一运行中任务必须幂等。
>
> **K02-F10 执行统一文档入库**：固定编排为采集校验→创建/更新待解析元数据→K02-F11 解析→K02-F12 规范化→K02-F13 分块→MySQL 事务写 document+全量 chunk→提交后触发 K03-F01；新文档先写 `raw_text=''`、pending 的壳；入库成功=parse_status=ready 且全量 chunk 事务提交；新建/编辑/升格必须幂等；任何入口不得绕过直接写 Milvus；情绪、未升格时间线、运行日志不接受入库。
>
> **K02-F11 解析**：PDF/DOCX/MD/TXT/HTML 分别使用对应解析器，网页剪藏先提取正文；解析开始显式置 pending，只有非空有效正文才 ready；加密 PDF、损坏文件、不支持编码、空正文或解析超时置 failed，保留原件、来源和错误摘要；**解析器不得执行文档内脚本、宏或外部资源**；页码、标题层级和来源位置必须尽可能保留，缺失用 null 不得虚构。
>
> **K02-F13 分块**：先按标题和段落分组，再在约 400~700 tokens 切分，相邻块保留 80~120 tokens 重叠；代码、表格和引用不跨结构随意截断；metadata_json 至少包含 documentTitle、docType、sourceUrl/sourcePath、headingPath、pageStart/pageEnd、charStart/charEnd；seq_no 唯一连续；content_hash 重复执行相同输入必须产生相同逻辑分块；全量新 chunk 单事务写入，编辑不得逐块覆盖导致新旧混合。
