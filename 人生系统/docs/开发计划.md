## 0. 工作流（贯穿全项目）

每个阶段固定四步，与 P0 已跑通的模式一致：

```
拍板范围与决策 → 我出任务书 prompt → 发给搭建模型 → 交付 → 我按任务书验收（含注释质量抽查）
```

- 任务书统一放 `docs/prompts/`，自包含（内嵌 schema/目录/枚举），模型读不到项目文件也能干活，读到则走用法 A。
- 交付物约束：行级中文注释（写"做什么+为什么"，禁模板句灌水）、禁止压缩代码（`minify:false`、不混淆、变量名不缩写）。
- 每阶段验收通过后才进入下一阶段，避免多轮工作混在一起难定位。

### 3.3 技术要点（架构文档已锁定）

- **Embedding**：Transformers.js + ONNX Runtime，跑在 Worker Thread，向主进程回传进度。`embedding_model_version` 变化 → 建新 collection/partition，全部新向量就绪才切活动版本。
- **Milvus**：唯一 collection `knowledge_chunk_v1`（chunk_id 主键、document_id、model_version、FLOAT_VECTOR[512]），COSINE + HNSW(M=16, efConstruction=200, 查询 ef=64)；10 万向量内不升级。chunk_id 必须能回查 MySQL；**严禁写入情绪记录**。
- **检索**：先 Milvus top20 → 去重 top6 → LLM。v1 不加 reranker。无 LLM 仍展示"相似资料"列表；无 embedding/Milvus 降级到 MySQL FULLTEXT 并提示。
- **索引一致性**：导入/编辑/升格在 MySQL 单事务写 document+全量 chunk 标记 `pending`，提交后异步 upsert Milvus；失败置 `failed` 保留原文+错误摘要+"重试索引"入口，不阻塞保存与全文搜索。启动轻量校验：`ready` 文档 chunk 数与 Milvus 命中数一致，异常转 `stale` 重建。
- **相关表**：`inbox_item`、`document`、`chunk`、`timeline_entry`、`mood_word`、`mood_record`、`mood_report`、`vector`（架构文档 4.2 已含全部 schema+索引）。
- **问答提示**：必须要求"无证据则明确不知道"，引用编号为不可省略输出约束。

### 3.4 P1 验收标准（任务书 §验收 追问式）

- [ ] 五种格式（MD/TXT/HTML/PDF/DOCX）均能入库并可追溯来源
- [ ] MySQL chunk 与 Milvus 向量最终一致（启动校验 + 重建入口）
- [ ] 每个回答引用真实原文，可打开定位（追问/引用 K03-F07）
- [ ] 情绪数据未出现在 FULLTEXT、向量、LLM RAG 请求（可脚本核查）
- [ ] 无 LLM 密钥时非 AI 模块全部可用 + 明确降级提示
- [ ] 一键备份已覆盖 MySQL+Milvus+原件，恢复后一致性校验通过
- [ ] AI 助手：多助手/多会话 CRUD 生效；会话历史落库、重进可恢复；上下文 = system prompt + 最近 20 条；LLM 失败时该轮用户消息回滚不落库
- [ ] typecheck / lint / test 全绿；注释质量达标（无模板句）
