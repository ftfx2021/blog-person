# 人生系统 · 设计文档（v0.2）

> 状态：产品定义阶段进行中（目标线已收敛，知识库线澄清中）
> 日期：2026-08-18

---

## 1. 项目定位

一个**个人目标与行动管理系统 + RAG 驱动的个人知识库**：

- **目标行动线**：把"人生目标"和"日常待办"分成两条独立又松耦合的流水线，让用户既能"想"（规划目标），也能"做"（执行行动）。
- **知识沉淀线**：把网页、PDF、Word、Markdown、自写文章集成为一体知识库，**以 RAG（检索增强生成）为核心能力**——系统第一版就包含语义检索与基于知识库的问答，而非可选项。

### 1.1 核心设计原则

1. **极简优先**：必须的只有 目标 + 待办(+习惯) + 知识库(+沉淀)；其他都是可选增强。
2. **目标与待办分离**：界面、交互、使用频率完全独立，数据上通过可空外键松耦合。
3. **投入 ≠ 结果**：目标进度由真实数据/真实完成驱动（称重、里程碑勾选），绝不根据行动次数换算。
4. **不做四象限**：待办没有"重要/紧急"判定，只有截止时间与状态。
5. **预留但不预付**：暂时用不到的能力（愿景、深度关联）只在模型上留插口，不提前实现。
6. **RAG 是第一公民**：知识库的存储与检索围绕 RAG 管线设计，不是后加的搜索功能。

### 1.2 目标与计划设计（核心结论）

必须的只有"目标"和"待办"两样，其余（项目/习惯/愿景）均为可选配件：年度目标、季度计划不建独立层级，统一为一层"目标"并用 `period` 字段（年度/季度/月度）标记周期，避免为管理而管理；待办完全独立于目标，日常待办（如交电费、打电话）不挂任何目标，待办/项目与目标之间以可空外键松耦合——挂上即出现在目标详情页"支持行动"区，不挂则毫无感知。目标本身不设固定形态，按度量方式分为三种：① 数值型——有天然单位（体重/金额/本数），设起点值与目标值，靠定期录入真实数据点推进度；② 里程碑型——抽象目标（如提高语言表达）拆成可勾选的子项，进度 = 已完成数/总数；③ 状态型——无法度量的目标（如改善睡眠）不设进度条，只标进行中/已完成/已放弃。无论哪种度量方式，进度都只由真实数据或真实完成驱动，绝不根据行动次数换算（投入 ≠ 结果）。一句话概括：系统只有两条必须的流水线，目标线管"想"，待办/习惯线管"做"，中间一根可选的虚线，用哪个装哪个，谁也不绑架谁。

### 1.3 知识库与沉淀设计（核心结论）

知识库与个人沉淀是两类性质不同的内容，分模块但用"升格"打通：知识库存**长期语料**（网页剪藏、PDF/Word 导入、Markdown 与自写文章、技能资产、Prompt 模板），核心诉求是"能搜到、能引用"，**由 RAG 语义检索驱动，第一版即为核心能力**；个人沉淀存**时间线记录**（日记、灵感、决策记录、阅读记录、项目复盘过程），核心诉求是"能回顾"，按时间线查看，默认不参与 RAG（隐私 + 低检索价值）。知识库入口前置一个**收藏箱 Inbox 暂存区**：各类收藏（网页/文章链接、片段、稍后读）先轻量暂存（链接 + 标题 + 备注），再经"剪藏入库 / 仅留链接 / 丢弃"处理，收藏是"过程"、知识库是"结果"；沉淀中证明有长期价值的条目（摘录、复盘结论、灵感成文）可一键升格进知识库，从此参与 RAG 检索；升格单向，时间线原记录保留。用户不需要在记录时决定归属——默认进暂存或时间线，值得的再升格。（心情/情绪记录不纳入沉淀，规划为独立的心理健康模块，见后续迭代。）

### 1.4 知识库长期语料结构设计

知识库的语料统一按"文档类型"组织，**所有类型一律参与 RAG 检索**（解析 → 分块 → 向量化 → 问答），差别只在采集方式与展示交互：

| 文档类型 | 采集方式 | 特征交互 |
|---|---|---|
| 网页剪藏（webpage） | 从收藏箱"剪藏入库"或知识库「导入网页链接」而来，抓取正文全文 | 来源 URL 记录 |
| 文件导入（pdf / docx / md / txt / html） | 本地上传，解析为纯文本 | 保留原文件路径 |
| 在线平台导入（飞书 / 语雀等） | 平台导出文件后手动导入；**未来以平台适配器接入 API**（方向声明，本期不实现，基线不调用平台 API） | 来源标注 |
| 自写文章（note） | 系统内手动撰写 | 富文本/Markdown 编辑 |
| 技能资产（skill） | 手动创建或升格 | 方法、代码片段等可复用知识 |
| Prompt 模板（prompt） | 手动创建、收藏箱剪藏或升格 | `usage_tags` 用途标签 + 一键复制按钮，**参与 RAG**（"我有没有写周报的 prompt"可直接检索到） |

所有文档共享统一元数据：标题、来源（URL/文件路径）、类型、标签、创建/更新时间；升格条目（promoted）额外保留指向沉淀/收藏的原始引用。**文档可导出为 pdf / markdown / txt**（导出不参与 RAG，仅格式转换）。

### 1.5 心理健康模块设计（核心结论）

心理健康模块是独立模块，不与目标/待办/知识库挂钩，也不纳入沉淀。核心是**情绪记录 + AI 分析**。记录采用**纯事件驱动**——只在有明显情绪波动时记一次深度记录（不做每日打卡），表单五要素源自《蔡康永的情商课》方法论：① 情绪命名——从内置细颗粒度词库选择（惆怅/遗憾/被背叛，而非模糊的"难过"），可自定义；② 强度——1~5 分；③ 事件——发生了什么，一句话；④ 情境——地点/和谁，可选（地雷区分析的原料）；⑤ 需求——"此刻我需要什么"，书中强调最易被忽略的一步（建议生成的锚点）。AI 分析由 **LLM 深度解读**驱动：统计图表（情绪分布、强度趋势）+ LLM 生成的周报总结与行动建议（"怎么办"导向，非心理诊断）。情绪记录存数据库普通表（单用户自用、不做特殊加密，已确认），**不进入知识库/RAG**——按时间回看，无检索需求。地雷区聚类分析（地点/人物/事件高频触发场景）依赖数据量，第二版再做。AI 定位为"自我觉察辅助"，报告措辞用"记录显示/你似乎"，不做诊断性表述。

### 1.6 项目交付管理设计（核心结论）

项目管理与交付是**独立模块**（与目标模块的 Project 互不相干，已确认），定位为**软件开发项目从创意到交付的完整管线**，由"创意漏斗 + 状态流"构成：① **想法收集**——低门槛随手记录项目想法（标题+描述，同知识库"收藏箱"的暂存哲学）；② **评估筛选**——对想法打分评估（价值/可行性），决定做不做（立项/暂缓/放弃，被否决的可复活）；③ **计划启动**——被选中的想法一键立项，创建正式项目；④ **开发状态流**——项目级状态流，阶段可自定义（默认：需求 → 开发 → 测试 → 交付 → 维护），交付即状态流最后阶段，不做版本发布记录等额外交付管理。MVP 提供：想法 CRUD 与评估打分、一键立项、项目 CRUD、自定义状态流、按阶段分组的看板视图（拖动切换状态）、项目详情（阶段进度）。与待办/目标暂不联动（开发任务挂载、里程碑节点、发布记录列入迭代候选）。

### 1.7 模块间关系设计（核心结论）

模块间关系遵循"少而精、全部可空、只建有回看价值"的原则，由两层构成：**模块内关系**（既有）——目标→项目→待办（可空外键）、收藏箱→知识库（剪藏）、想法→开发项目（立项）、沉淀→知识库（升格）；**跨模块关系**——**沉淀时间线 = 叙事中枢**，沉淀条目（日记/复盘/灵感/决策）通过通用关联表 `entity_link` 可关联任意实体（目标、生活项目、待办、知识文档、开发项目、情绪记录等），0~n 全部可选、双向可见（backlink），例如一条项目复盘可同时关联开发项目、期间完成的目标、产出的知识文档。**明确不建**：情绪↔其他实体（MVP，敏感且回看价值低）、知识文档↔目标/项目（无明确场景）、待办→开发项目（迭代候选）。注：系统无独立"日程"实体，复盘关联的是具体实体（待办/项目）而非日期概念。

### 1.8 系统主动性设计（核心结论）

系统人格定位为**被动底座 + 分级主动**（已确认）：记录与检索是核心价值，主动性全部可配置、默认克制。主动性分三级：**一级 · 关键提醒**（默认开）——目标到期、习惯打卡、该录入数据了，落在对应页面站内提示，唯一不需要数据积累的主动性；**二级 · 周期报告**（生成但不打扰）——情绪周报、目标进展复盘，站内可查看、通知可关闭；**三级 · 主动推荐**（默认关）——根据状态推荐候选行动/建议，**只呈现选项、确认后才执行，绝不自动动作**（延续"人拍板"哲学）。通知渠道**仅站内聚合**（打开系统可见，无桌面/邮件推送，已确认）。任何一级都有独立开关与频率控制，可随时降噪；三级推荐依赖数据量，随使用自然演进。**Dashboard 首屏布局：主区 = 今日行动（待办 + 习惯打卡），次区 = 目标进展摘要卡片**——首屏主操作是"做"，目标进展是辅助回看信息（待办为日活粘性来源，目标为周频回看）。

### 1.9 成功衡量指标（核心结论）

系统成功衡量遵循"个人工具无商业 KPI"原则，只回答两个问题：是否持续用（行为）、生活是否变好（结果）。已确认框架：**北极星 = 每周深度使用天数**——一周内有几天完成核心动作（记录数据/复盘/查看周报/立项）之一，同时代表"在用"与"在想"；**行为指标**——复盘持续率、情绪记录保持率、待办完成率、逾期率，证明各模块被真实使用；**结果指标**——首要为**降低焦虑**（心理健康模块情绪记录自评趋势：负面情绪强度中位数/频率，标注为自评趋势而非因果结论），次要为目标完成率（须配难度评估，防设低目标游戏化）、知识找回步数。**护栏**：不追求使用时长/打开次数，完成率不做排名、无惩罚。指标用途**仅自我观察**（洞察页辅助自我调整，不干预系统行为）；洞察页**第二版再做**（所有数据已在记录，跑一个月后展示）。

### 1.10 失败模式与防线（核心结论）

系统失败模式与防线（已确认）：**首要风险是功能复杂难坚持**（死于迷茫）——防线为四大模块入口极简、交互统一（"暂存→处理"哲学贯穿）、高级选项默认折叠、每个页面只突出一个主操作；**录入负担**（次于复杂度）——用极简模板压低写作成本：复盘为固定 3 问模板，情绪记录默认只填"命名+强度"、情境/需求折叠；**数据安全**——MVP 即提供 MySQL + Milvus 备份与导出（逻辑库 dump/快照 + JSON/Markdown），防死于事故；**价值保障**——回看体验优先，复盘模板、周报、RAG 问答优先做精，让系统真正帮助决策，功能广度其次。隐私不纳入风险（用户已确认单用户自用）。

### 1.11 系统边界（核心结论）

**首版为桌面端应用（Electron）**，不做 Web 与移动端（移动端列入迭代）；**单人使用**，无多人协作。**离线优先**：MySQL 与 Milvus 默认部署在本机，核心数据操作不依赖公网；仅 AI 调用时联网（**本地 embedding + LLM API 混合**：embedding 用本地小模型，问答/周报用 API，已确认）。若改为远端 MySQL/Milvus，则核心功能依赖到服务的网络连接。**知识库导入**：pdf/word/md/txt/html 文件导入 + 在线平台（语雀等）手动导出文件后导入（API 同步列入迭代）；**导出**：pdf/markdown/txt + MySQL/Milvus 一键备份。**技术栈**：Electron + Vue3 + 全 JS/TS 生态（文档解析、向量检索均在 JS 生态实现）。开发周期不限时（边学边做，周期服从质量）。

## 2. 信息架构

系统由两大模块组成：

```
模块A 目标与行动（"想" + "做"）
┌──────────────────────────────────────┐
│ 规划层：Goal 目标 ──period 年度/季度/月度
│           └── Project 项目（可选容器）
│ 执行层：Task 待办（可挂项目/目标，可空）
│          Habit 习惯（打卡，第一版）
└──────────────────────────────────────┘

模块B 知识库与沉淀（"学" + "记"）
┌──────────────────────────────────────┐
│ 知识库：Document 文档（网页/PDF/Word/Markdown/文章）
│          └── Chunk 分块 ──→ 向量索引（RAG）
│ 沉淀：  Timeline 条目（日记/灵感/决策/阅读/复盘）
│          └── 可"升格" → 知识库
└──────────────────────────────────────┘
```

### 2.1 目标行动线层级

| 层级 | 必须? | 说明 |
|---|---|---|
| 目标 Goal | **必须** | 模块A心脏；周期用 period 字段（年度/季度/月度），不分层嵌套 |
| 项目 Project | 可选 | 达成目标的一组行动（如"马拉松训练"）；可不挂目标 |
| 待办 Task | **必须** | 独立一等公民；goal_id / project_id 均可空，不强制挂钩 |
| 习惯 Habit | 第一版纳入 | 重复性行动打卡，连续天数统计 |
| 人生愿景 | 暂缓 | 不建表；后续需要时在 Goal 上加可选 vision 字段即可 |
| 领域/分类 | **不建实体** | 持续关注点（健康/职业等）用**自由标签 tags** 归类，目标/项目可打可空，不建强制层级 |

### 2.2 知识库与沉淀线内容归属

| 内容 | 归属 | 说明 |
|---|---|---|
| 收藏箱 Inbox（各类收藏） | 知识库前置暂存区 | 链接/片段/稍后读先轻量暂存，可剪藏入库、仅留链接或丢弃 |
| 网页收藏（剪藏） | 知识库 | 由收藏箱处理而来，参与 RAG |
| PDF / Word 导入 | 知识库 | 解析为文本后入库，参与 RAG |
| Markdown / 自写文章 | 知识库 | 长期语料，参与 RAG |
| 技能资产（方法/代码） | 知识库 | 可检索复用 |
| Prompt 模板 | 知识库 | 复用资产，usage_tags 标签 + 复制交互，参与 RAG |
| 阅读摘录 | 沉淀 → 可升格 | 摘录先挂阅读时间线，值得引用的升格入库 |
| 项目复盘 | 沉淀(过程) + 可升格(结论) | "怎么做的"走时间线；"下次怎么做"可入库 |
| 日记 / 灵感 | 沉淀 | 时间线回顾，不参与 RAG |
| 决策记录 | 沉淀 | "当时为什么这么选"，决策审计用 |
| 心情 / 情绪 | 独立心理健康模块（后续） | 不纳入沉淀；追踪逻辑（频率/趋势）与沉淀不同 |

## 3. 数据模型

### 3.1 实体关系

```
Goal 1───* Project 1───* Task
 │                        │
 ├──* GoalRecord          └──* Habit? (习惯独立)
 └──* Milestone

Document 1───* Chunk ──* VectorIndex（RAG 检索）
InboxItem（收藏箱暂存）──剪藏→ Document
TimelineEntry（多类型：日记/灵感/决策/阅读/复盘）
  └── promote → Document（升格）
```

### 3.2 表结构

```
goal           目标
  id, title, description?
  period:        annual | quarterly | monthly
  metric_type:   numeric | milestone | status
  unit?, start_value?, target_value?      -- numeric 型
  status:        active | done | abandoned
  tags?                  -- 自由标签（健康/职业等持续关注点归类，可空）
  created_at, updated_at

goal_record    目标数据点（numeric 型的进度来源）
  id, goal_id → goal
  value, recorded_at
  note?

milestone      里程碑（milestone 型的进度来源）
  id, goal_id → goal
  title, done: boolean, done_at?, sort_order

project        项目（可选容器）
  id, title, description?
  goal_id → goal        -- 可空
  status: active | done | paused
  start_at?, end_at?
  tags?                  -- 自由标签，可空

task           待办（独立一等公民）
  id, title, note?
  goal_id → goal        -- 可空，默认空
  project_id → project  -- 可空，默认空
  due_date?             -- 排序依据
  status: todo | doing | done
  created_at, completed_at?

habit          习惯（第一版）
  id, name, note?
  frequency:  daily | weekly_times(n)
  streak, last_done_at

document       知识库文档（RAG 语料源）
  id, title, doc_type: webpage | pdf | docx | markdown | note | skill | prompt | promoted
  source_url?, file_path?, raw_text
  usage_tags?          -- prompt/技能资产 的用途标签
  created_at, updated_at

inbox_item     收藏箱条目（知识库前置暂存区）
  id, url?, title, note?, kind: link | snippet | read_later
  status: pending | clipped | bookmarked | discarded
  promoted_to_document_id?   -- 剪藏后指向知识库文档

chunk          文档分块（RAG 检索单元）
  id, document_id → document
  content, seq_no, meta_json（标题/页码/来源）

vector_index   向量索引（由 chunk 向量化产生）
  chunk_id → chunk
  embedding, model_version

timeline_entry 沉淀条目（多类型时间线）
  id, type: diary | idea | decision | reading | review
  content, tags?
  promote_to_document_id?   -- 升格后指向知识库文档
  created_at

mood_record    情绪记录（心理健康模块，纯事件驱动）
  id, mood_word            -- 词库选词或自定义
  intensity 1~5
  event                   -- 发生了什么（一句话）
  context?                -- 地点/和谁（可选）
  need?                   -- 此刻我需要什么
  is_custom_word: boolean
  recorded_at

dev_project    开发项目（项目管理模块，独立）
  id, name, description?
  stages: JSON            -- 自定义阶段列表，默认 ["需求","开发","测试","交付","维护"]
  current_stage_index: int
  status: active | done | paused | archived
  repo_url?               -- 可选代码仓库链接
  created_at, updated_at

project_idea   项目想法（创意漏斗入口）
  id, title, description?
  status: inbox | evaluating | approved | discarded | launched
  value_score?, feasibility_score?    -- 评估打分 1~5
  evaluation_note?
  launched_to_project_id?             -- 立项后关联 dev_project
  created_at, updated_at

entity_link    通用关联（沉淀叙事引用，跨模块）
  id
  from_type, from_id       -- 来源实体（如 timeline_entry）
  to_type, to_id           -- 目标实体（goal/project/task/document/dev_project/mood_record…）
  relation?                -- 可选语义标签（如"复盘目标"/"涉及项目"）
  created_at
```

### 3.3 进度计算规则

| metric_type | 进度来源 | 公式 |
|---|---|---|
| numeric | goal_record 最新数据点 | (最新值 − start_value) ÷ (target_value − start_value)，夹在 0~100% |
| milestone | milestone.done | 已完成数 ÷ 总数 |
| status | 无进度条 | 仅状态标记（进行中/已完成/已放弃） |

> 明确不做：任务/习惯打卡次数 → 目标进度 的任何换算（投入 ≠ 结果）。

### 3.4 关联规则

- 待办/项目挂目标是**可选**的，创建时目标选择器默认折叠、默认空白。
- 挂目标待办的唯一效果：出现在目标详情页的"支持行动"区；不挂则完全无感。
- 无目标的待办、无目标的项目均合法。
- **UI 命名区分**：目标模块的 Project 显示为"项目"（目标→项目语境），项目管理模块的 DevProject 显示为"开发项目"（全称 + 图标/配色区分），避免认知混淆。
- **待办单归属**：最多 1 个目标 + 1 个生活项目（均可空）；里程碑不直接挂待办（目标是其内部拆解载体）；多目标场景走 entity_link 叙事引用。
- 习惯为独立实体（不合并为可重复待办）：数据行为（streak/打卡历史）、交互（打卡 vs 勾选）、心理模型（坚持 vs 完成）均不同。

### 3.5 RAG 数据流（第一版核心）

```
采集        解析            分块          向量化        检索问答
剪藏/上传 → 提取纯文本 → 按段落/语义切块 → embedding → 语义检索 top-k
手动撰写  （PDF/DOCX/网页）  （带元数据）  （本地模型   → LLM 生成
                                         或 API）      （回答附引用）
```

- 单用户规模，向量库使用 Milvus Standalone；MySQL 保存业务事实和 chunk 元数据，Milvus 保存可重建向量。
- 检索可加 rerank；回答必须带引用来源（对应 chunk → document）。

### 4.1 新建待办流程（零负担保证）

1. 默认视图：只有一个标题输入框（+ 可选截止时间）。
2. "目标/项目"为折叠的高级选项，不展开则完全不出现。
3. 提交后待办直接出现在列表，无任何强制选择。

### 4.2 沉淀升格流程

1. 时间线条目上出现"升格为知识库"操作。
2. 升格时可选：原样入库 / 编辑后再入库（生成 document，promote_to_document_id 回填）。
3. 升格后该条目进入 RAG 语料，时间线原记录保留。

## 5. MVP 范围界定

### 第一版包含
- 目标：三种度量类型完整实现（numeric 数据点 / milestone 勾选 / status）
- 项目：CRUD，可挂/不挂目标
- 待办：CRUD + 截止时间排序 + 按目标/项目筛选 + 可选挂载
- 习惯：打卡 + 连续天数
- 目标详情"支持行动"区（列出挂在该目标下的待办）
- 知识库：网页剪藏 + PDF/Word/Markdown/TXT/HTML 导入 + 语雀等平台文件导入 + 手动撰写 + 文档管理 + 导出（pdf/md/txt）
- 收藏箱：存链接/片段 + 剪藏入库两条路径（丢弃顺带）
- Prompt 模板：知识库类型之一，usage_tags + 复制交互
- **RAG：分块 → 向量化 → 语义检索 → 问答（带引用）——第一版核心**（本地 embedding + LLM API）
- 沉淀：日记 / 灵感 / 决策记录 三种时间线条目 + 升格机制
- 心理健康：情绪记录五要素 + 内置细颗粒度词库 + AI 周报（统计图表 + LLM 总结建议）
- 项目管理：想法收集 + 评估筛选 + 一键立项 + 项目 CRUD + 自定义状态流 + 看板分组/拖动切换
- 站内关键提醒（目标到期/习惯打卡/数据录入提示，一级主动性，仅站内）
- 一键备份与导出（MySQL dump + Milvus 快照 + JSON/Markdown）+ 一键恢复（选备份文件还原；**版本历史/冲突检测不做**，列入未来"数据迁移与备份中心"候选）

### 第一版明确不做
- 人生愿景模块（模型留插口）
- 习惯关联到目标（后续按需）
- 任何形式的优先级/四象限
- 阅读进度/书单管理（沉淀里只有阅读摘录）
- 多端同步、外部渠道推送
- 社交/分享

## 7. 架构设计输入（边界已定，待出架构方案）

已确认：
- 桌面端 Electron + Vue3，全 JS/TS 生态；数据库 MySQL 8（单用户免认证）
- RAG：本地 embedding + LLM API（DeepSeek 等）；向量库使用 Milvus Standalone
- 知识库导入：pdf/docx/md/txt/html 文件 + 语雀等平台导出文件；导出 pdf/md/txt

- 进程模型（Electron 主进程直管 vs 内置 Node 服务）、IPC 与数据访问模式
- 桌面端打包方案（electron-builder / forge）
- MySQL 与 Milvus 的双存储一致性、部署与备份方式
- 无 AI 时的降级路径（断网/无密钥时系统仍可用）
