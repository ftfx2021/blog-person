## 四、必须整改的问题

### 1.【P0 级，功能不可用】设置页一键恢复是伪实现
> **⚠️ 更正批注（2026-08-20 复核）**：本条目原判断有误。主进程侧已实现文件选择——`src/main/ipc/backup-handlers.ts:24-34` 在 `manifestPath === "SELECT"` 时调用 `dialog.showOpenDialog` 弹出原生对话框，且 `backup:restore` 已注册（`lifecycle.ts:16`）。**恢复链路可用，不需要从零实现对话框**。真实待改的是：① UI 无二次确认（`confirmation` 硬编码）；② dialog 缺 `parent`/`defaultPath`；③ 结果反馈。整改清单见 `docs/prompts/P0整改任务书.md` §三。
- `src/renderer/features/settings/SettingsPage.vue:82`：`manifestPath: "SELECT"` 硬编码字符串，未提供 UI 二次确认，用户点「恢复」后直接触发主进程文件选择，误操作风险高。
- 影响：验收项 6 的「恢复」缺少安全确认与可用性优化（默认目录、父窗口）。
- 整改：恢复按钮应先在 UI 弹确认框（提示将覆盖当前数据库），确认后调用 `backup.restore`；主进程对话框补 `parent` 与 `defaultPath`（backups 目录）。

### 2.【P0 级，违反硬约束 10】注释密度 0.9%，36 个文件零注释
统计（脚本：`scripts/_count_comments.py`）：

| 面积 | 行数 | 注释 | 占比 |
|---|---:|---:|---:|
| src 全部 TS/Vue (56 文件) | 4368 | 38 | **0.9%** |
| 其中零注释文件 | 36 | 0 | **0%** |
| 迁移 SQL（001_initial_schema.sql） | 296 | 52 | 17.6% ✅ |

零注释的重灾区（按优先级整改）：
- **服务层**：`modules/goals|tasks|habits|projects|settings|backup/service.ts`、`modules/dashboard/service.ts`、`modules/search/service.ts` —— 每个业务分支（状态机判断、进度计算、streak 回算、备份安全点、导出 hash）要求行级中文注释
- **IPC 层**：`ipc/handlers.ts`、`ipc/backup-handlers.ts`、`ipc/result.ts`
- **渲染层全部 Vue 页面**：重点 `GoalDetailPage.vue`（288 行 0 注释）、`SettingsPage.vue`、`DashboardPage.vue` 的 script 逻辑块
- **基础设施**：`db/pool.ts`、`filesystem/paths.ts`、`shared/contracts/*.ts`
- 备注：`shared/domain/*`（progress/state-machines/streak）已有少量注释但不足 10%，需补充「为什么」说明

### 3.【P1 级】tag 名称去重大小写不一致
- `modules/common/database.ts` `replaceTags` 用 JS `Set` 去重（大小写敏感），而 `tag.name` 唯一索引是 `utf8mb4_0900_ai_ci`（大小写不敏感）。`['Coding','coding']` 会触发 Duplicate entry。
- 整改：统一按 `COLLATE` 语义去重（转小写比较）或捕获唯一键冲突并合并。

### 4.【P1 级，建议】`scripts/check-ipc-schemas.mjs` 有效性弱
- 现脚本只能发现「绕过 registerHandler 直写 ipcMain.handle 忘 parse」，无法校验 preload 与主进程 schema 一致性（当前靠人工核对，已核对一致）。
- 建议增强：对比 `preload/api/index.ts` 的 channel 集合与 `ipc/handlers.ts` 注册集合，不一致即报错。

### 5.【观察项】非缺陷
- 今日行动查询把无截止日期待办也纳入（`dashboard/service.ts:13` `due_date IS NULL OR DATE(due_date)<=today`）：与「今日行动=今日到期项」口径存在出入，建议与 FSD H01-F01 详述核对，若 FSD 无明文则以「无日期待办常驻今日行动」为设计意图，不改。
- `checked_on`/`last_done_on` 用 DATE 而非 DATETIME(3)：架构文档 schema 为 TEXT，按「本地自然日」语义用 DATE 更严谨，可接受。
- 迁移 runner 的 beginTransaction 对 DDL 因 MySQL 隐式提交而形式化：已在 docs/database-design.md 与注释中声明，属已知限制，可接受；失败不写版本记录保证可续跑，符合任务书意图。
