## 二、解析器锁定（架构 §3.2，违反即返工）

| 格式 | 库 | 必须保留 | 禁止 |
|---|---|---|---|
| PDF | **pdfjs-dist** | 逐页文本 + 页码定位 | pdf-parse、只取首页、扫描 PDF 假成功 |
| DOCX | **mammoth** | 标题层级 → headingPath | 解压 XML 正则抽文本 |
| HTML/网页 | **cheerio + turndown** | 先去噪（script/style/nav/header/footer）再转 Markdown | cheerio 全量文本带导航噪音 |
| Markdown | **unified/remark**（AST） | 标题层级 → headingPath | split 硬分块、markdown-it 渲染去标签 |
| TXT | Node 流式 | 编码检测 UTF-8/UTF-16、段落切分 | 不处理编码、无大小上限 |
| 手写/升格 | — | 跳过文件解析，**不得跳过规范化与分块** | 直接写库绕过 K02-F10 |

## 三、统一入库防简化硬规定（K02-F10）

1. **元数据壳**：新文档先写 `raw_text=''` + `parse_status=pending` + `index_status=pending` 的壳记录（保留来源/原件），解析失败 → `failed` 壳 + 原件 + 错误摘要；编辑不得用壳覆盖旧可用版本
2. **幂等**：同一运行时任务 ID 重放不得重复建 document；同来源同内容（raw_text hash 比对）必须提示复用或仍新建，**禁止静默覆盖**
3. **事务**：document + 全量 chunk 单 MySQL 事务提交；编辑失败保留旧正文/旧 chunk/旧索引；新向量 ready 前不删旧向量（P1-5 落实删除）
4. **任何入口不得绕过 K02-F10 直接写 Milvus**；情绪数据、未升格时间线不接受入库
5. 原件先复制到 `data/documents/`（决策 D2），复制失败不得开始入库
