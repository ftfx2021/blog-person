# P1-知识库多库结构决策

> 日期：2026-08-21　状态：**已拍板**　关联：`docs/prompts/知识库多库结构任务书.md`
> 触发：用户要求知识库升级为语雀式——多个知识库 + 库内子文件夹 + 富文本编辑 + 标签统一管理 + Milvus collection 组织方式。

## 一、背景

当前知识库是**单库平铺**：`document` 表无归属字段，Milvus 单一 `knowledge_chunk_v1` collection（chunk_id/document_id/model_version/embedding）。用户确认目标形态为语雀式（见交互演示），要求落地。

## 二、拍板结论（K1~K7）

| # | 决策点 | 结论 | 理由 |
|---|---|---|---|
| K1 | **Milvus 组织方式** | **单一 collection + kb_id/folder_id 标量字段过滤**（不按库拆 collection，不用 partition） | 个人本地应用、单用户数万 chunk：运维最简单（备份/恢复/embedding 模型切换只动 1 个 collection）；知识库增删改不碰 collection；检索带 filter 即可限定库范围。拆库/partition 适合多租户强隔离，不适用 |
| K2 | **collection 命名与升级** | 新 collection **`knowledge_chunk_v2`**（字段集加 kb_id/folder_id），存量向量**迁移**而非丢弃重嵌入 | v1 字段集固定（enable_dynamic_field=false）无法原位加字段；换新名可回退 |
| K3 | **存量数据迁移** | 首次迁移建「默认知识库」，所有存量文档自动归入；Milvus 存量 chunk 经 `exportAll(v1) → join MySQL document 补 kb_id/folder_id → importAll(v2)`，行数校验一致后切换默认 collection | 禁止清库重建、禁止丢向量；不重新 embedding（向量本身不变，只补标量归属） |
| K4 | **数据模型** | 新增 `knowledge_base`、`knowledge_folder`（parent_id 树形，支持多级）；`document` 加 `kb_id`、`folder_id` 可空外键；`chunk` 表**不加列**（归属经 document join，Milvus chunk 上冗余 kb_id/folder_id 供过滤） | 文档归属唯一（一文档一库）；文件夹不跨库；chunk 归属由 document 推导，避免双写不一致 |
| K5 | **删除规则** | 库下有文档 → **禁止删除**（提示先移动/清空）；文件夹下有文档或子文件夹 → **禁止删除**；不提供静默级联删除 | 保护数据，语雀同款语义 |
| K6 | **文档移动** | 移动文档 = 更新 MySQL 归属 + **同步 Milvus chunk 的 kb_id/folder_id**（upsert 同主键覆盖），两步同一事务意图，失败可重试 | 只改 MySQL 会导致按库过滤检索失效 |
| K7 | **标签管理** | `tag` 表 CRUD + **重命名全局生效**（UPDATE tag.name，entity_tag 自动跟随）+ 按标签浏览入口；复用现有 entity_tag 多态表 | 标签是跨库横向关联，与库/文件夹正交 |

## 三、与其它阶段的衔接

- **P1-4（文档导入）**：解析/规范化/分块/统一入库管线**不动**；只在其入库入口增加"选库/选文件夹"参数
- **知识库增强（OCR/Chromium/原件）**：不动
- **P1-5（RAG）**：**必须基于本结构出任务书**——检索接口预留 `kbId` 过滤参数（单库问答=filter，全局问答=无 filter）；`ai_assistant.knowledge_base_id` 预留列届时对接
- **收藏箱剪藏**：剪藏入库时选目标库/文件夹（默认上次选择）

## 四、风险与对策

| 风险 | 对策 |
|---|---|
| v1→v2 迁移丢数据 | 迁移先导出 v1 全量（含行数），importAll 后 count 比对，不一致即中止并回退默认 collection 名；迁移前要求用户先备份（复用一键备份） |
| 文档移动后过滤失效 | 移动接口强制同步 Milvus（delete+upsert）；验收含"移动后按库搜索命中"用例 |
| 文件夹循环引用 | parent_id 校验：不允许指向自己/后代 |
| 新库太多反而难检索 | 产品引导：库 = 话题域（3~6 个起步），文件夹管库内组织，标签管跨库横向——不设技术上限但 UI 提示合理数量 |

## 五、明确不做（本期）

- 不按库拆 collection（K1 已定）；不做 partition
- 不做文档拖拽（拖放排序/移动）——本期移动用菜单/按钮，拖拽放 P2
- 不做库级权限/共享（单用户）；不做库封面自定义（仅名称+可选图标色）
- 不重新 embedding 存量向量（K3）
- 不动解析管线与 OCR/Chromium/原件功能
