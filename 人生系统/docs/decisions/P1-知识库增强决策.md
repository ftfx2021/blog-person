## 二、K-1 OCR 设计

**设置项**（受控键 `knowledge.ocr`，设置页「知识库 → OCR」区块）：
- `provider`：`baidu | tencent | aliyun | tesseract | disabled`（默认 `disabled`；配置了对应密钥才可选在线）
- 三家密钥：`safeStorage` 加密存储（沿用 `llm.chat` 模式），**不进 manifest/导出/日志**：
  - 百度：`apiKey` + `secretKey`（client_credentials 换 token）
  - 腾讯：`secretId` + `secretKey` + `region`（TC3-HMAC-SHA256 签名，默认 `ap-guangzhou`）
  - 阿里：`accessKeyId` + `accessKeySecret` + `endpoint`（RPC 签名，默认 `ocr-api.cn-hangzhou.aliyuncs.com`）
- 在线三家**手搓签名/请求**（百度 OAuth2、腾讯 TC3、阿里 RPC），**不引入云 SDK**（保持零框架依赖，符合项目风格）

**流程**（在 `knowledgeService.ingest` 解析步骤扩展）：
1. `PdfParser` 无文本 → 抛 `OcrRequiredError`（不再是普通失败）
2. ingest catch 到 OCR 错误 → `ocrService.recognize(pdfPath)`：
   - 按设置 provider 顺序：在线三家（配置了密钥才尝试）→ 失败/未配置 → 本地 `tesseract.js`（chi_sim+eng）→ 都失败才置 failed + 错误摘要
   - 尝试顺序：`baidu → tencent → aliyun → tesseract → failed`（按配置可用性跳过）
3. OCR 文本作为 rawText 继续规范化/分块；**扫描件无页码定位**（pageLocations=null，metadata 相应字段 null）
4. 每次 OCR 结果在错误摘要/任务状态记录来源（哪家 OCR）

**PDF 转图**（在线/本地 OCR 都需要）：pdfjs 每页 `render` 到 canvas → PNG buffer。
- **新增依赖 `@napi-rs/canvas`**（Node 侧 canvas，**原生模块**，electron-builder 打包需 rebuild）
- 页码按顺序送 OCR，文本按页序拼接

**新增依赖**：`tesseract.js`（WASM，语言包 chi_sim+eng 随应用打包）、`@napi-rs/canvas`（原生）

## 三、K-2 Chromium 网页抓取设计

`fetchWebpage` 替换为**隐藏 BrowserWindow 渲染抓取**：

1. 每次抓取创建**隔离 session**（`session.fromPartition("webpage-fetch-" + 随机)`），页面无法污染默认会话
2. 隐藏窗口（`show:false`、`sandbox:true`、`contextIsolation:true`、`nodeIntegration:false`）
3. 防副作用：`setWindowOpenHandler` deny 弹窗、`will-download` 阻止、禁 file:// 导航
4. `loadURL(url, { timeout: 设置值 })` → 等待 `did-finish-load` 且 body 非空（DOM 渲染完成）→ `executeJavaScript("document.documentElement.outerHTML")` 取整页 HTML → `win.destroy()`
5. 失败（`did-fail-load` / 超时 / 403 页面内容识别）→ 销毁窗口 → 抛可读错误（含"网站拒绝访问，可保存网页后导入文件"的引导文案）
6. 抓到的 HTML 交给既有 `HtmlParser`（cheerio 去噪 + turndown），管线不变
7. 串行抓取（一次一个窗口），超时上限沿用设置值

**替换**：`knowledge/index.ts` 的 `fetchWebpage`（Node fetch 版删除或保留为不可用时的降级——本任务直接替换，不再走 fetch）。

## 四、K-3 原件操作设计

- `knowledge:openOriginal` ← `{ id }`：读 `stored_path`，校验文件存在 → `shell.openPath(path)`；无原件/不存在 → `NOT_FOUND`
- `knowledge:saveOriginal` ← `{ id }`：`dialog.showSaveDialog`（defaultPath=原件原名）→ `fs.copyFile(stored_path, 选中路径)`
- Preload：`knowledge.openOriginal` / `knowledge.saveOriginal`
- 详情页：有 `storedPath` 显示两个按钮；无则禁用（tooltip「无原件」）
- 安全：路径来自数据库（应用自写目录），不接收渲染层任意路径
