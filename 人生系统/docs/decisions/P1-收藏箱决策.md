# P1 决策记录：收藏箱（inbox_item）边界与 snippet 转文档补丁

> 日期：2026-08-21　状态：**已拍板**　关联：`docs/functional-spec.md` K01、`docs/architecture.md` §4.2 `inbox_item`、`docs/开发计划.md` §3.2 P1-3/P1-4
> 背景：P1-3 收藏箱与 P1-4 文档导入存在管线依赖（K01-F03 剪藏入库强依赖 K02-F10 统一入库）；FSD K01-F03 未定义 snippet（纯文字片段）转文档的路径。以下拍板补齐。

## 一、剪藏入库的依赖边界（并行开发契约）

| # | 决策点 | 拍板结果 | 说明 |
|---|---|---|---|
| B1 | 网页抓取与统一入库归属 | **P1-4 实现**：网页正文抓取（HTML 解析器）、K02-F10 统一入库（K02-F11 解析→K02-F12 规范化→K02-F13 分块→MySQL 事务→K03-F01 索引）均属 P1-4 范围 | K01-F03 规定"抓取结果必须交给 K02-F10"，而 K02-F10 是 P1-4 功能 |
| B2 | P1-3 剪藏入口形态 | P1-3 定义**入库端口契约** `knowledgeService.clipToDocument(...)` 并以"未实现占位"交付（抛 `INGEST_UNAVAILABLE`）；P1-4 任务书**替换该占位**为真实管线。P1-3 验收按降级路径（提示+收藏不丢）通过，P1-4 验收补端到端 | 保证 P1-3/P1-4 可并行搭建、互不阻塞 |
| B3 | 新增错误码 | `errorCodeSchema` 末尾新增 `INGEST_UNAVAILABLE`（「文档入库管线未就绪」） | 语义区别于 `DB_UNAVAILABLE`/`AI_UNAVAILABLE`/`VECTOR_DB_UNAVAILABLE` |

## 二、snippet（片段）转文档补丁

| # | 决策点 | 拍板结果 | 说明 |
|---|---|---|---|
| B4 | snippet 剪藏入库 | **允许**。snippet 剪藏 = 直接用已有内容（`note`，无 note 用 `title`）创建 `doc_type=note` 文档，**不抓取**（无 URL），走统一入库；成功后 `status=clipped` 并回填 `document_id` | 补 FSD K01-F03 缺口：原文仅 link/read_later 可剪藏 |
| B5 | 字段校验 | snippet 无 URL 时必须有 note（沿用 FSD K01-F01 规则②）；snippet 剪藏时 note 为空且 title 为空不可能（title 必填） | — |

## 三、其余沿用（不改）

- `inbox_item` 表结构沿用 P0 迁移（id/kind/url/title/note/status/document_id/时间），**无需新迁移**
- 状态机沿用 FSD：pending →（剪藏）clipped /（仅留）bookmarked /（丢弃）discarded；discarded → pending；clipped 不直接删文档
- 无"硬删除"操作：丢弃即移出主列表，可从 discarded 恢复
- 新增收藏不抓取、不进 RAG（K01-F01 规则③）
- 剪藏失败：document 壳记录 `parse_status=failed`（K02-F10 处理），inbox 保持 pending 可重试，**不得丢 URL**
