# 第五章 系统详细设计与实现

## 5.1 用户管理详细设计

### 5.1.1 用户注册实现

注册表单提交后，前端组件收集用户名、密码与邮箱字段，调用API模块中的注册方法向后端发送POST请求。UserController接收请求参数，调用UserService的注册入口方法。该方法首先通过Mapper查询数据库判断用户名和邮箱是否已存在，验证通过后调用BCrypt工具类对明文密码执行哈希加密，随后封装User实体对象并调用Mapper的插入方法完成数据落库。

注册功能后端核心处理方法如下所示：

```java
public void createUser(User user) {
    QueryWrapper<User> wrapper = new QueryWrapper<>();
    wrapper.eq("username", user.getUsername());
    if (userMapper.selectOne(wrapper) != null) {
        throw new RuntimeException("用户名已存在");
    }
    wrapper.clear();
    wrapper.eq("email", user.getEmail());
    if (userMapper.selectOne(wrapper) != null) {
        throw new RuntimeException("邮箱已被注册");
    }
    user.setPassword(BCrypt.hashpw(user.getPassword(), BCrypt.gensalt()));
    user.setStatus(1);
    userMapper.insert(user);
}
```

### 5.1.2 用户登录实现

用户在登录页输入凭证并触发登录事件，前端调用登录API方法发送POST请求。UserController接收用户名和密码参数，转交UserService的登录方法处理。该方法通过Mapper按用户名查询数据库获取用户记录，调用BCrypt的校验方法比对明文密码与密文是否匹配，同时检查用户状态字段是否为正常。校验全部通过后使用JWT工具类生成令牌，令牌载荷中写入用户ID和角色编码。

登录功能后端核心处理方法如下所示：

```java
public Map<String, Object> login(String username, String password) {
    QueryWrapper<User> wrapper = new QueryWrapper<>();
    wrapper.eq("username", username);
    User user = userMapper.selectOne(wrapper);
    if (user == null || !BCrypt.checkpw(password, user.getPassword())) {
        throw new RuntimeException("用户名或密码错误");
    }
    if (user.getStatus() == 0) {
        throw new RuntimeException("账号已被禁用");
    }
    String token = JwtUtils.generateToken(user.getId(), user.getRoleCode());
    Map<String, Object> result = new HashMap<>();
    result.put("token", token);
    result.put("user", user);
    return result;
}
```

## 5.2 文章管理详细设计

### 5.2.1 文章创建实现

管理员在文章编辑页填写内容并点击保存，前端收集标题、正文、分类、标签列表与封面图数据，调用创建文章API发送POST请求。ArticleController接收请求后委托ArticleService处理。Service方法首先将Markdown内容转换为HTML格式，处理封面图片的存储路径，然后调用ArticleMapper插入文章记录。插入完成后遍历标签ID列表，逐条调用ArticleTagMapper插入关联记录。事务提交后通过RabbitTemplate向消息队列发送事件，触发文章的异步向量化流程。

文章创建的标签关联与消息发送逻辑如下所示：

```java
public void addArticle(Article article, List<Long> tagIds) {
    article.setHtmlContent(MarkdownUtil.parse(article.getContent()));
    article.setStatus(1);
    articleMapper.insert(article);
    if (tagIds != null && !tagIds.isEmpty()) {
        for (Long tagId : tagIds) {
            ArticleTag at = new ArticleTag();
            at.setArticleId(article.getId());
            at.setTagId(tagId);
            articleTagMapper.insert(at);
        }
    }
    rabbitTemplate.convertAndSend(
        ArticleRabbitMqConfig.ARTICLE_EXCHANGE_NAME,
        ArticleRabbitMqConfig.ARTICLE_VECTORIZED_ROUTING_KEY,
        article.getId()
    );
}
```

### 5.2.2 文章列表查询实现

用户访问前台首页或文章列表页时，前端调用分页查询API发送GET请求，携带当前页码和每页条数参数。ArticleController接收参数后调用ArticleService的分页查询方法。该方法构建分页查询条件，设置状态为已发布，按置顶和创建时间降序排列，调用ArticleMapper执行分页查询。查询结果返回后，Service层遍历文章列表，依次查询分类名称、作者信息和关联标签，将这些附加信息填充到每篇文章的返回对象中。若用户已登录，还会批量查询当前用户对这些文章的收藏状态。

文章列表查询的核心分页逻辑如下所示：

```java
public IPage<Article> getArticlesByPage(int page, int size, Long categoryId) {
    Page<Article> pageParam = new Page<>(page, size);
    QueryWrapper<Article> wrapper = new QueryWrapper<>();
    wrapper.eq("status", 1);
    if (categoryId != null) {
        wrapper.eq("category_id", categoryId);
    }
    wrapper.orderByDesc("is_top").orderByDesc("create_time");
    IPage<Article> result = articleMapper.selectPage(pageParam, wrapper);
    for (Article a : result.getRecords()) {
        a.setCategoryName(categoryMapper.selectById(a.getCategoryId()).getName());
        a.setAuthor(userMapper.selectById(a.getUserId()).getName());
        a.setTags(tagMapper.selectByArticleId(a.getId()));
    }
    return result;
}
```

## 5.3 评论互动详细设计

### 5.3.1 评论提交实现

用户在文章详情页评论区域输入内容并点击提交，前端调用评论创建API发送POST请求。CommentController接收评论数据后调用CommentService的添加方法。该方法先通过ArticleMapper校验目标文章是否存在，若评论为回复类型则验证父评论是否存在且属于同一篇文章。校验通过后将评论状态设为待审核，调用CommentMapper插入评论记录，随后通过ArticleMapper将对应文章的评论计数加一。

评论提交的核心处理逻辑如下所示：

```java
public void addComment(Comment comment) {
    Article article = articleMapper.selectById(comment.getArticleId());
    if (article == null) {
        throw new RuntimeException("文章不存在");
    }
    if (comment.getParentId() != null && comment.getParentId() > 0) {
        Comment parent = commentMapper.selectById(comment.getParentId());
        if (parent == null || !parent.getArticleId().equals(comment.getArticleId())) {
            throw new RuntimeException("父评论不存在");
        }
    }
    comment.setStatus(0);
    commentMapper.insert(comment);
    article.setCommentCount(article.getCommentCount() + 1);
    articleMapper.updateById(article);
}
```

## 5.5 知识库与AI问答详细设计

### 5.5.1 知识库问答实现

用户在知识库问答页面输入问题并提交，前端使用原生fetch方法向后端流式接口发送POST请求。KnowledgeController接收问题文本后调用KnowledgeBaseService的问答方法。该方法先调用EmbeddingService将问题文本转换为语义向量，随后以该向量为查询条件在Milvus向量数据库中执行相似度检索，返回语义最接近的若干文档片段。Service将检索到的文档片段与原始问题组装为提示词，调用Spring AI的ChatClient向大语言模型发起流式请求。

知识库问答的流式响应构建逻辑如下所示：

```java
public Flux<String> streamAskWithDocs(String question, List<Document> docs) {
    String context = docs.stream()
        .map(Document::getContent)
        .collect(Collectors.joining("\n\n"));
    String prompt = "基于以下参考内容回答问题：\n" + context + "\n\n问题：" + question;
    return chatClient.prompt()
        .user(prompt)
        .stream()
        .content()
        .map(chunk -> "data: " + chunk + "\n\n");
}
```

## 5.6 站点配置详细设计

### 5.6.1 博客设置获取与更新实现

管理员进入博客设置页面时，前端调用配置查询API发送GET请求。BlogConfigController接收请求后调用BlogConfigService的查询方法，该方法通过BlogConfigMapper从blog_config表中读取全部配置记录，以键值对列表形式返回。管理员修改配置项并点击保存后，前端将配置列表通过PUT请求提交到后端。Service方法遍历提交的配置列表，对每个配置项判断是否已存在：已存在则调用BlogConfigMapper的更新方法，不存在则调用插入方法新增记录。

博客设置的批量更新逻辑如下所示：

```java
public void updateBatchConfig(List<BlogConfig> configs) {
    for (BlogConfig config : configs) {
        QueryWrapper<BlogConfig> wrapper = new QueryWrapper<>();
        wrapper.eq("config_key", config.getConfigKey());
        BlogConfig existing = blogConfigMapper.selectOne(wrapper);
        if (existing != null) {
            existing.setConfigValue(config.getConfigValue());
            blogConfigMapper.updateById(existing);
        } else {
            blogConfigMapper.insert(config);
        }
    }
}
```

## 5.7 数据统计详细设计

### 5.7.1 仪表盘数据加载实现

管理员进入仪表盘页面，前端调用仪表盘数据API发送GET请求。DashboardController接收请求后调用DashboardService的统计方法。该方法分别调用ArticleMapper、CommentMapper和UserMapper的计数方法获取文章总数、评论总数和用户总数，遍历文章表统计所有已发布文章的浏览量总和作为总访问量。随后查询最近七天内按日期分组的文章发布数量和访问量数据，连同最近发布文章列表和最近评论列表一并封装返回。

仪表盘的核心指标聚合逻辑如下所示：

```java
public Map<String, Object> getDashboardData() {
    Map<String, Object> data = new HashMap<>();
    data.put("articleCount", articleMapper.selectCount(
        new QueryWrapper<Article>().eq("status", 1)));
    data.put("commentCount", commentMapper.selectCount(null));
    data.put("userCount", userMapper.selectCount(null));
    data.put("totalViews", articleMapper.sumViewCount());
    data.put("recentArticles", articleMapper.selectRecent(5));
    data.put("recentComments", commentMapper.selectRecent(5));
    return data;
}
```

### 5.8.2 首页句子随机展示实现

用户访问博客首页时，前端在页面加载阶段调用随机句子API发送GET请求。MySentenceController接收请求后调用MySentenceService的随机查询方法。该方法构建查询条件筛选is_show字段为1的记录，调用MySentenceMapper的随机查询方法从结果集中随机返回一条句子记录，前端将返回的句子文本和来源信息渲染到首页指定区域。

首页句子的随机查询逻辑如下所示：

```java
public MySentence getRandomSentence() {
    QueryWrapper<MySentence> wrapper = new QueryWrapper<>();
    wrapper.eq("is_show", 1);
    List<MySentence> list = mySentenceMapper.selectList(wrapper);
    if (list == null || list.isEmpty()) {
        return null;
    }
    int index = new Random().nextInt(list.size());
    return list.get(index);
}
```
